# Admin panel · id: H6 · status: Draft · version: 1

## In one sentence
Admins change the server's settings from inside the game with `/admin`: pick a config file, click a setting, and the new value is checked, saved, applied and logged, with no file editing and no restart for most settings.

## How it works
- **`/admin`** (alias `/config`) lists every loaded config file, about 45 files and over 1,300 settings (counted in the code). It is generated from the typed config classes, so a new module or setting appears by itself.
- **A file** shows each setting as a button with its description, current value, default, allowed range and choices. Changed settings are marked. A file with a problem shows a red torch.
- **Click to edit:** true/false switches, choices cycle, whole numbers use a number picker, text and decimals use chat input, lists open a list editor.
- **Every change** is validated, saved to the YAML file, applied live by reloading the owning module, and logged (`config/edit` with old and new value). Settings that need a restart say "Needs a restart" and the confirmation says "Applies after restart".
- **Two levels** (`ConfigEdits`): admin settings need `skyblock.admin.config`; owner settings (many economy and season settings, retention, folders) need `skyblock.owner.config`. Admins see owner settings but they are locked: "Only the owner can change this."
- **Hidden:** `database.yml` (it holds secrets) never shows.
- **The staff hub `/staff`** (alias `/staffmenu`, `skyblock.staff.menu`) is the front door. Buttons by permission: Display (chat, tab and nametag format), Config editor, Titles & Tags, Staff mode, Logs, Reports, Vanish, Staff chat, Modules, Worlds, Island grid, NPCs & Holograms, Tutorial stats.
- **Console side, `/skyblock`:** `modules`, `reload [core|module]`, `config [file]` (active values), `worlds`, `tp <world>`, `builds`, `style`.
- **Not in `/admin`:** message texts (`messages/*.yml`) and `punishments.yml`. They are edited as files (the owner uses GitHub), checked by the build, and reloaded with `/skyblock reload`. A broken file is rejected and the old one stays.
- **Planned (decided): emergency buttons (628).** The owner gets one-click buttons for sell prices, shop prices and interest. Every use is logged. Not built.
- **Planned (decided): clean up dead settings (R3-16, REVIEW3 §3 fix 6).** Delete the old 30-minute keys, `islands.yml disband-prompt-length` and `homes.*`, and `shop-settings.yml buy.confirm-above`, so `/admin` shows only settings that do something. A test keeps dead keys from coming back.

## What the player sees
- Players see nothing. This is staff only.
- Admins see a paged list of files ("Settings: N, You can edit: N, Changed: N"), then a paged list of settings.
- Reply after a click: "<file> » <setting>: old to new. Live now." or "wasn't changed: <reason>".
- Staff with `skyblock.admin.reload` are told about config problems when they join (a `core.yml` setting, on).
- Bedrock: everything is a menu button, a number picker or one chat line. No file paths to type.

## Rules and limits
- A wrong value is refused with a reason. The old value stays active.
- Only the owner can change owner-level settings. Every change is in the audit log with who, file, setting, old and new.
- No hardcoded numbers or texts: every feature keeps its numbers in a config that appears here.
- Performance: the menus read cached config info. A change reloads one module, not the server.
- Safe on new versions: new settings are added with their default; existing values are never overwritten.
