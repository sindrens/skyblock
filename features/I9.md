## In one sentence
One standard and one FORMAT that every menu, tooltip, title, shop grid, scoreboard, tab, bar, hologram and message follows: four panel types (3, 4, 6 rows and the 7 x 4 list) with compact centred layouts, fixed buttons in fixed slots, short plain tooltips (coloured name, one grey sentence, one yellow `» ACTION` line) and one vanilla base item for every icon that our cartoon icon repaints; for Java players with the pack the panel gets a plaque with cartoon lettering and only slots that hold items are drawn (a minimal custom font, V3-Q1), everyone else gets the same layout on the plain vanilla chest.

## How it works

### 1. The eight rules
1. **Vanilla text, vanilla items, vanilla sounds.** Everything a player reads (tooltips, lore, chat, messages, holograms, boss bar, action bar, scoreboard lines) is normal text in the vanilla font. An icon is always a real vanilla item whose own look and our name explain it. The pack may only add: icons repainted on base items, and (if V3-Q1 says yes) the **frame layer** (panel, plaque, lettering, soft tiles, logo). Nothing needs the pack to be understood.
2. **One plain click does it.** Left click (Java) or tap (Bedrock) does the main thing on every button. Right-click and shift-click are optional Java shortcuts; their hint lines are not shown to Bedrock players.
3. **Same place every time.** Back, pages and Close are always in the same slots (section 4); the summary or wallet tile is slot 4; the danger tile is slot 8.
4. **Colour = meaning** (section 8), and every colour state also has a shape (`✔ ✘ ●`).
5. **Less is more.** A screen shows what most players need now, grouped, with space between groups. Unbuilt features are hidden (41, GUI-1 G2). Empty slots are not drawn (section 3).
6. **Nothing can be taken out of a menu** (all click types, drag, number keys, offhand are blocked).
7. **Help is in the world** (NPC and hologram help, A5; the hub's Help button; `/help <topic>`); lore stays short; no `?` button (GUI-Q5).
8. **One FORMAT.** A new feature copies a template of section 15 and `docs/FORMAT.md`; it never invents a look. The checklist of section 17 must be all yes before a screen ships.

### 2. Panel types and centred layouts
Chest screens are 9 columns wide; only the row count changes (1 to 6). The plain layer shows a vanilla chest; the frame layer (V3-Q1) draws a panel of the **same window size** over it. Exactly **four panel types** (5-row menus are not used; `MenuLayout` keeps 5 for old code until migrated):

Legend: `S` summary or wallet tile (4), `D` danger tile (8), `B` Back, `A` `A` screen actions, `X` Close, `Q` Search (auction house only), `P` `N` previous and next page, `t` tabs, `c` content, `g` grid slot.
- **Which panel:** one content row (up to 9 tiles) = `P3`; two content rows (up to 14 tiles) = `P4`; three or four content rows, grids, tabs plus content and trees = `P6` (the `/menu` hub has four groups on four rows, so it is `P6`). Tabs go on row 0; when row 0 holds the summary or wallet tile, tabs go on row 1. A screen never changes panel while open.
- **Centred spread patterns** (column numbers 0-8; same on every menu): 1 button = 4; 2 = 3 and 5; 3 = 2, 4, 6; 4 = 1, 3, 5, 7; 5 = 0, 2, 4, 6, 8. Groups of different meaning get an empty column or row between them.
- **Item grids** (7 wide, columns 1-7): an **odd** row is contiguous and centred (1: 4; 3: 3-5; 5: 2-6; 7: 1-7); an **even** row splits around the centre column with a gap (2: 3,5; 4: 2,3,5,6; 6: 1,2,3,5,6,7). One group per row; groups longer than 7 split evenly (9 = 5 + 4). `Centered.grid(rowCounts)` is the pure helper.
- **Slot 4 of row 0** is the summary or wallet tile; **slot 8** the danger tile; nothing else in row 0 except tabs.
- **Symmetry:** with an odd number of choices the middle one is the most common one.
- Decided (GUI-Q4, owner): compact, empty slots stay empty.

### 3. Hidden empty slots, soft tiles and the filler rule
- **No border frame and no filler panes** (as v2). A pane may only mark a state (a red pane in an error item); no pane has a tooltip.
- **Plain layer (Bedrock, no pack):** an empty slot is drawn by the client as a vanilla cell; nothing can change that, so the layout is the same and only less crowded.
- **Frame layer (pack, V3-Q1 and V3-Q2):** the panel has **no slot cells**, so an empty slot is simply not visible. Every slot that holds an item gets a **soft tile** (an 18 x 18 cell glyph) behind it, composed per open from the slots that are filled (V3-Q3: tiles or floating items). The player's own inventory half is drawn with normal cells. The vanilla hover highlight still shows on hover.
- The tile set changes only when a slot becomes filled or empty (a live tile appearing), then the title is re-sent in place (`titleUpdateInPlace`, as v1 did on page turns); nothing is re-sent while only item text changes.
- A panel is **one colour for all menus** (V3-Q9); the area colour lives on tile names only.

### 5. Danger-action rule
- Delete island, delete profile, reset, disband, leave, permanent ban, destroy items: **one tile each, base item TNT with our own red danger icon in pack v2 phase 1** (owner, GUI-Q7), red name (`error` colour), red `» CLICK to ...` line, two short grey lines saying exactly what is lost.
- Placed in a **corner that is not next to Back, the page arrows or the main action** (default slot 8, top right; on menus with tabs the slot at the far end of the content block). Never in the centre.
- A click opens the existing `ConfirmMenu`; things that cannot be undone use `twoStep()` (second screen swaps the sides and says "Last check: this can't be undone"). Details and costs go on the middle item (13), not on the green button, so Bedrock players read them before tapping.
- Confirm tile = lime concrete, cancel tile = red concrete (own icons in phase 1); both are big enough to hit on a phone. The danger icon (TNT) is used for nothing else; Close stays a barrier.

### 6. Tooltip and lore template (one builder: `LoreBuilder`, texts in module message files)
```
Island Upgrades                        name: bold, colour = area meaning (section 8), no italics
Make your island better.               ONE grey sentence (`text` colour, wrapped at 32-36 characters)

| Level: 3 / 9                         optional section(s), at most 2: bold red `| Header`, dark red bar, grey label, white value
| Next: $12,000

» CLICK to open                        bold `action` yellow, verb UPPER CASE, always the last line (a footer like RARE TOOL comes after)
```
- A menu button is at most **6 lines**: name, one sentence, up to 3 info lines, one action line. Help text goes in `?`, NPCs and holograms, not the lore (owner 44).
- **Price lines** (shop, sell chest, AH): bold `BUY` and `SELL` style as in UI_STYLE §4.1: `| Buy Price: $8 each` (bold green), `| Sell Price: $2 each` (bold red, muted `Not sellable` when impossible). Currency amounts keep their currency colour.
- **Live note:** one coloured line only when a price moves: `Falling: -4% today` (orange) or `Rising: +6% today` (green). Words, not arrows (arrows are not Bedrock-safe). Shop buy prices are fixed (C5-Q3), so the note normally belongs to the sell price.
- **Java-only hint:** a muted line such as `Right-click: sell` or `Shift-click: buy a stack` appears only for Java viewers. The action line always names the plain click.
- Names are **plain and bold, coloured by meaning** (section 8; owner GUI-Q6). Action symbol `»` (on the Bedrock-safe list). Tooltip names have **no brackets**: in chat a yellow `[Word]` means "clickable" (`[Confirm]`, `[Accept]`), and a tooltip name must never look like a chat button (GUI-Q6). Category tags in chat events (`[Crate]`, G1) and hologram or NPC names (`[ Banker ]`, A5) are not tooltips and use their own colour, never the action yellow.
- Hide vanilla attributes, enchant lists and potion text; custom enchanted items keep the glint. Lore is generated from data, never edited by hand.
- **v3 limits (decided, V3-Q16 a, I9-R2-08; enforced by a ratchet test):** at most 6 lines per tile (the shop tile 7), at most 36 characters per line, at most 2 `| Header` sections of at most 3 rows each, exactly one `» CLICK` line and it is last, at most one muted Java hint line. Tooltips and lore never use the custom font (readable on every client).
- **Wallet tile:** one per screen that spends, slot 4, currency icon, name `Your Money` in the currency colour, the full amount; costs in lore are `| Cost: $12k`. No balance in every tooltip (V3-Q8).

### 7. Icon rules (vanilla+)
1. Every menu button has a **base item** that explains it on its own (the map in UI_STYLE §5.5, extended in section 9). Two buttons on one screen never share a base item.
2. A pack model is an **optional repaint**: the same base item plus a `custom_model_data` string, sent only to viewers whose pack status is LOADED (`PackService.hasPack`). The material never changes (v1 swapped everything to PAPER; v2 does not), so a missing pack, a declined pack, Bedrock or a failed download all show the real base item.
3. **Never `item_model` pointing at a pack-only model**: a client without the pack draws the purple-and-black missing model. The one exception is `item_model` pointing at another **vanilla** model (for example `minecraft:golden_pickaxe` on the tier "gold" tool, built in `ToolItems`): that works for every Java client with no pack at all.
4. **Bedrock** never receives a pack model and never sees one (Geyser needs extra mappings and a Bedrock pack for that; not planned). Name and base item carry the meaning.
5. Back and page arrows use vanilla items (arrow, paper), not textured player heads. Heads stay only for people (profile, members, visit lists).
6. **Style of our own icons (owner, GUI-Q9):** the old v1 icons are discarded. New icons look like vanilla Minecraft items, simple, clearly different from each other and readable at a glance by every kind of player, new or old, Java or phone. The owner draws them (I7).
7. Counts are allowed as information (ready count, page number); they work on Bedrock.
8. Locked, loading, error, empty, ready, selected and toggle states keep today's looks (UI_STYLE §5.1): gray dye with `✘ Name`, clock `⌛ Loading...`, red glass `✘ Couldn't load this`, cobweb `Nothing here yet`, count plus glint plus `● 3 ready`, glint plus `✔ You are here`, lime dye `✔ On` / gray dye `✘ Off`.

### 10. Hotbar menu item, paging, titles, sounds
- **Menu item (as built, `MenuItem`):** a Nether Star named `Menu` in the last hotbar slot (slot 9); `» CLICK to open`. It cannot be dropped, moved, stored or lost; switch in `/settings` per profile (decided 50). Same slot and icon always (MC Hub does the same).
- **v3 (decided, V3-Q7 a, I9-R2-04): a natural vanilla Nether Star.** The `menu` catalogue icon (a repainted star) and the red-glint look are dropped: the item is the plain vanilla Nether Star model, name `Menu` in flame gold, lore `» CLICK to open`. The build checks whether the vanilla star already glints on its own (the Nether Star is a foil item in vanilla); only if it does not does the item keep `setEnchantmentGlintOverride(true)`. `HIDE_ENCHANTS` and the PDC marker stay. Result: it looks like the item every Minecraft player knows, on Java and Bedrock alike.
- **Paging:** 28 entries per page. Plain layer: page number in the title `(2/5)` and as the count on the arrow. Frame layer: the page is the count on the arrow items only (the plaque holds the noun). More than 5 pages means tabs or a pick menu instead.
- **Titles, plain layer (unchanged):** vanilla font, a short noun in Title Case (`Shop`, `Island » Upgrades`), at most 2 parts and 32 characters (`title.max-parts`, `title.max-length`), the red `▸` marker and gray crumbs; confirm titles are a verb and its object (`Disband island?`).
- **Titles, frame layer (decided, V3-Q4 a):** the **plaque** shows ONE short noun in the cartoon lettering (caps): `SHOP`, `UPGRADES`, `FARMING`, at most 16 letters (plaque `S` up to 8, `M` up to 12, `L` up to 16, chosen from a letter-width table); the parent crumb is dropped because Back says where you came from; confirms are `DISBAND?`; no page number, no balance, no state in the plaque. A title that does not fit 16 letters is a message-file bug caught by the test; at run time it falls back to the plain title (never cut). The lettering maps normal ASCII characters, so a narrator reads the real words.
- **Sounds:** the vanilla set in `sounds.yml` (click, menu-open, page, success, error, notify ...). One sound per kind of event, the same everywhere; `error` on every refusal. No custom sounds (V3-Q17).

### 11. Search and lists (owner, GUI-Q10: search only in the auction house)

## Rules and limits
- Max 6 lines per button tooltip; max 36 visible characters per line; no italics; only Bedrock-safe symbols (UI_STYLE §2.1).
- No pack-only information: nothing important is readable only with the pack or only in hover text (the key fact is in the name or the middle item).
- Every menu has Back (except `/menu`) and Close.
- Performance: menus are built when opened and refreshed in place; per-viewer render is a map lookup; price lookups come from the 1 s cache; no per-tick work.
- Security: unchanged (debounce, no item removal, all value moves in one ledger transaction).
- **Frame layer rules (decided):** one custom font family, used only for panel, plaque lettering, soft tiles and logo; text that carries information (lore, chat, messages, holograms, boss bars, scoreboard lines) never uses it. Every font surface is per viewer: `Glyphs.of(viewer)` returns nothing for Bedrock, no-pack, fail-open and "Plain menus" viewers.
- A custom glyph is never sent to a client that cannot draw it: an unknown font id shows missing-character boxes on Java, and Bedrock shows blanks or its own emoji for private-use code points (so codepoints start at U+E300 and the Bedrock sheets U+E0xx and U+E1xx are never used).
- The plaque never carries information that is not also in the tile text (the plain title is always sent as the real string).
- The plaque sits 8 px above the window edge (`plaque_extend`, a pack constant), so it stays on screen at GUI scale 3 on a 720p window (a 6-row window has 9 px above it).

### v3 additions (decided with the V3 answers; exact classes and steps in `GUI-FONT.md` and `MENUS-V3.md`)
- **`PanelTitle` (new, pure, `common/menu`):** `build(PanelType, BitSet filledSlots, Plaque, String lettering)` returns the title string of one font run (space glyphs, panel glyph, one soft tile per filled slot, plaque, then the lettering component in `phoenix:title`). Golden-string tests: the cursor returns to the origin, the number of tiles equals the filled slots, a title over 16 letters is refused (falls back to the plain title). `Glyphs.of(viewer)` is the only factory and takes the viewer (empty for Floodgate, no-pack and "Plain menus" viewers).
- **Menu open becomes two-phase:** items are built into the layout first, then the title is composed from the filled slots, then the inventory is created (today `service.title(...)` runs before the items). In-place refresh re-sends the title only when the filled-slot set changed; **Paper 26.3 `InventoryView` has only `setTitle(String)`, which cannot carry a font, so a frame title is updated by swapping the inventory** (`GUI-FONT.md` 6.6; the spike checks flicker and the cursor).
- **`Centered.grid(int... rowCounts)`** (pure) gives the slots of a grid with one group per row (odd rows contiguous, even rows split around the centre column); `ShopGrid` (pure, shop module) turns groups into pages (whole groups, up to 4 rows).
- **Config:** `menus.yml` `gui.font.enabled` (true), `gui.font.panels`, `gui.font.titles`, `gui.font.tiles`, `gui.font.logo` (all true), `gui.font.title-resend-min-ms` (500); the plaque extension (8 px) is a **pack constant** (`plaque_extend` in `resourcepack/frame/panels.json`: it is baked into the glyph ascent); message files get `title.short` (the plaque noun) next to the plain crumb; the settings are typed and editable in `/admin`, `/skyblock reload core` applies them. Setting `gui.font.enabled` false turns the whole frame layer off at once (rollback with no deploy).
- **Accessibility (developer decision, may be vetoed; extends GUI-P9 "no pack switch" only for text style):** one per-profile `/settings` entry `Plain menus` (default off) for players who prefer vanilla titles and cells; the narrator reads the real title words either way (the lettering uses ASCII code points).
- **Safety:** `PrivateUse.strip` stays on all player text (nobody can type a panel glyph); no player text is ever placed in a panel title; the plaque noun comes only from message files.
- **Performance:** a title is composed once per open (and per filled-slot change), cached in a small LRU keyed by (panel, filled mask, plaque, text); no per-tick work; each panel PNG is one texture.
- **Migration order:** framework (`PanelTitle`, `Glyphs`, two-phase open, `Centered.grid`), `/menu`, shop, island menus, then module by module with the `title.short` keys; staff screens last.
- **Hotbar star:** `MenuItem#create` stops calling `menus.icon(player, "menu", ...)`; the catalogue row `menu` is deleted from `icons.json` (GUI-P1 build spec slice 1 becomes 9 icons); nothing else changes.
