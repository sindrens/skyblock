# Messages and texts · id: G4 · status: Built · version: 1

## In one sentence
Every text a player sees comes from a message file, one per module, in one short plain format, so the owner can change any word without a developer.

## How it works
- **Rule:** all player-facing text stays in `messages/<module>.yml`. No text in code (REVIEW3 F10).
- **Files:** `messages/<module>.yml`. The repo holds 36 files, about 12,600 lines (the REVIEW3 note counted 33). On the server they sit in `plugins/PhoenixSkyblock/messages/`. Edit, then `/skyblock reload` (or `/skyblock reload <module>`). New keys are added on updates and your edits are kept.
- **Markup:** MiniMessage with house tags from `style.yml`: `<c:text>`, `<c:value>`, `<c:action>`, `<sym:check>`, `<grad:phoenix>`. Player text is never parsed, so nobody can inject tags.
- **The format** (UI_STYLE §3, UX1/UX2):
  - Prefix `PHOENIX »` on replies to something the player did. Never on broadcasts, lists, lore, scoreboard, titles or the action bar.
  - Success: green ✔ and gray text. Error: red ✘, gray text, and the fix in a few words.
  - Names, amounts, commands: white. Clickable parts: yellow `[Accept]` with a hover text. Asides: gray in brackets.
  - Plain words. No "Please", no "successfully".
- **Shared command texts** (`commands.yml`): usage line (click fills it in), unknown word, players only, cooldown, confirm, player offline, never joined, bad amount, bad time, bad choice.
- **`&` colour codes** work where people type colours: ranks, nicknames, broadcasts (UI_STYLE 1.6b).
- **Numbers:** short in menus (`1.2M`), full in chat and `/bal` (owner answer 32). Typed amounts like `10m` work; tab completion shows no amount hints (#48).
- **Aliases and cooldowns** live in `commands.yml` (server root). Every command has tab completion.
- **Safety nets:** many modules have a `MessagesTest` that checks every key exists. `/skyblock style` previews the palette, symbols and message types.

## What the player sees
- Example reply: `PHOENIX » ✔ Paid $5,000 to Steve. Balance: $12k`
- Example error: `PHOENIX » ✘ You need $2,000 more. Sell items with /sell.`
- Wrong command input: `PHOENIX » ✘ Steve doesn't fit here. Usage: /is create` with a click to fill in.
- Unknown command: "Unknown command. Type /help or /menu." (`spigot.yml`).

## Rules and limits
- Bedrock: only the safe symbols in `style.yml` (`✔ ✘ » ▸ ·` and a few more). Gradients show only their first colour. Hover text is a bonus, never the only place for needed information.
- English only, always (owner answer 31).
- Not ours yet: vanilla death messages, "server full", whitelist and outdated-client screens, and texts of other plugins (LuckPerms, Geyser, ViaVersion, Grim, FastAsyncWorldEdit). Most of those only staff see. REVIEW3 F10 wants every message saved in a file, so these are the gap (open question 3).
- Performance: messages are parsed when sent. Fixed texts without placeholders are parsed once per viewer type.

## Connections
- Every feature card uses this format. Chat (G1), tab and scoreboard (G7, G8), menus and help (G9, G10).
- Admin panel (H6) edits configs; messages are edited as files.
- Islands (B cards): the new 48 h slot-lock texts go in `messages/islands.yml` (REVIEW3 F10).
- Resource pack (I7): the `PHOENIX »` prefix can become a small logo glyph.

## Decided
- 31: English only.
- 32: big numbers short in menus, full in chat and `/bal`.
- 34: compact messages for all players, Bedrock changes later only if needed.
- 44: Bedrock never needs long commands.
- UX1, UX2: clean, short, direct messages with normal words, one colour scheme, one format. All message files rewritten.
- STYLE2: brighter v2 palette, red identity, bold yellow `» ACTION` lines, red `|` bars.
- 500, 519: ban and mute announcements are public (rule number only) unless `-s`.
- 579: join message for money received offline, max 5 lines then "and N more".
- REVIEW3 F10: all player-facing text must stay in `messages/<module>.yml` (it does today); no text in code. Every new text goes in the module's file, and all messages are saved somewhere.

## Open questions
All of these are proposals in MESSAGES_AND_COMMANDS.md. Defaults are the doc's suggestions.
1. Name 9 message types (reply, error, warning, info, usage, request, confirm, list, broadcast) and use them for every message? (default: yes)
2. A command with no arguments opens its menu, and `/<command> help` prints a short list, 8 lines per page with `[Next]`? (default: yes)
3. Restyle the vanilla texts players see (unknown command with "did you mean", server full, whitelist, outdated client, kicks)? Death messages: PvP deaths only to players in the warzone, other deaths only to the player who died? (default: yes)
4. REVIEW3 F10 makes "no text in code" the rule. Add a build test that fails when a player text is written in code instead of a messages file? (default: yes)
5. Review all messages on one clickable page per module (OK / Change / Other), player files first? (default: yes)

## Rejected ideas
- In-game editor for messages: edit files and reload instead, less to break (doc suggestion).
- Amount hints like `10k 10m 10b` in tab completion (#48).
- Emoji shortcuts such as `:heart:`: only a short Bedrock-safe symbol list works.
