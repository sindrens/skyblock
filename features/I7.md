# Resource pack · id: I7 · status: Draft · version: 1

## In one sentence
A forced resource pack gives the server its own look (menu backgrounds, item icons, font icons, sounds) on top of the vanilla game, and everything still works without it.

## How it works
Two plan docs exist (RESOURCE_PACK.md and RESOURCE_PACK_ART_BRIEF.md). No pack code or art exists yet. The first release waits for the owner's art (RP1).
- **Built (groundwork only):**
  - Items can carry a pack model (`ItemDefinition.itemModel`); with no pack they show the vanilla item.
  - Every menu already uses fixed slots, so the pack can only paint on top.
  - `server.properties` has the five pack lines empty and `require-resource-pack=false`.
- **The pack only paints** (plan). Same slots, clicks and items. Without the pack you see today's vanilla UI.
- **Forced on Java** (RP-D1): sent in the configuration phase, before you enter the world, with a short professional prompt. Declining disconnects you with a how-to. Bedrock gets a converted pack through Geyser.
- **Sent by the plugin** from `pack.yml` (url, sha1, id, required), not by `server.properties` (RP-D2, proposed default). Hosting: `pack.skybornmc.net` on the VPS, a CDN later (RP-D5, proposed default).
- **Per-player rendering** (proposed default): the plugin knows if you have the Java pack, the Bedrock pack or neither. Glyphs, backgrounds and pack sounds go only to players who can show them.
- **What each side gets:**
  - Java: menu backgrounds, item models, font icons, HUD bars, worn set looks, sounds, border texture.
  - Bedrock: item icons, font icons, sounds. No menu backgrounds, 3D models, HUD bars or worn armor.
- **Item looks** use a `custom_model_data` string on a vanilla item (RP-D3, proposed default), so a missing pack shows the vanilla item.
- **Milestones** (proposed default): RP1 plumbing, RP2 font icons, RP3 menu backgrounds, RP4 item models, RP4b worn set looks, RP5 Geyser, RP6 sounds, RP7 HUD, RP8 crates, RP9 world border, RP10 launch.
- **Art list:** 427 entries (505 files). 238 entries are needed for the first release: GUI backgrounds (52), menu buttons (34), tools (61), wardrobe sets (86), crate keys and blocks (14), currency icons, 8 sounds. The owner draws everything himself.

## What the player sees
- Joining on Java: a download prompt on the loading screen (size target 8 MB), then menus with phoenix art, new item icons, currency and rank icons in chat, and custom sounds.
- Bedrock: the converted pack with icons and sounds; menus keep the vanilla frame.
- Prompt and decline texts will be in `messages/core.yml: pack.*`.
- Version bump: online players get the new pack after `/skyblock reload` with a one-line notice.

## Rules and limits
- Never send what a client cannot draw: no pack model, glyph or sound id goes to a player without the pack.
- Download failure: let the player in on the vanilla look and alert staff, never lock everyone out (RP-D18, proposed default). Emergency: `pack.required: false` and reload turns it into an optional offer.
- The `/settings` pack toggle is hidden while the pack is required.
- Size targets: Java zip 8 MB (hard 20 MB), Bedrock 5 MB (hard 10 MB), download under 3 s at 25 Mbit/s.
- Art must be original: no copied Mojang or third-party textures. The pack id never changes; the version number does.
- Known doc drift: the art brief's rank badge group (§N) still lists the old rank names (Squire, Knight...) instead of Ashborn, Hatchling to Immortal (REVIEW3 §3). Fix it before badges are drawn.
- Bedrock rules: every menu is chest-based with no chat clicks. Pack text uses glyphs only where Bedrock has them (shared icons start at U+E200).
- Performance: the pack is cached by the client; the server only sends a hash and URL. No per-tick work.

## Rejected ideas
- Licensed or AI-made art: the owner draws all art himself (77).
- A general Java-to-Bedrock converter: the plan uses a small own converter for icons, glyphs and sounds only, which is simpler and predictable (RP-D9).
