## In one sentence
A free rank for everyone, 7 permanent bought ranks and 3 ranks won for one season, plus 5 staff ranks. Bought ranks give looks and convenience; gameplay power is never sold (R3-7). Staff are bold caps in bright colours, donors are normal case in their own colours.

### 4. How LuckPerms, chat.yml and the surfaces work together
- **One look per group id.** `chat.yml ranks.looks` has one line `group=#hex|&code` per LuckPerms group (I7-R1-04). It draws the badge `[Display name]` on chat, tab, nameplate (one scoreboard team per player), `/list` and the sidebar; the name takes the look colour. Bold comes from `&l` in the Bedrock code (RANKS-COLORS spec). The LuckPerms display name is the badge text; the LuckPerms prefix and `color` meta are only the fallback and for other plugins, and a unit test (`RankConsistencyTest`) keeps them equal to the look.
- **Tab order.** The tab list sorts by team name `pxs<999 - weight><name>`: higher weight first, then A to Z (weights must stay 0 to 999). Prefix priority equals the group weight, so a higher rank always wins the prefix.
- **Proposed new weights** (one migration with the donor build; old prefix priorities are removed first): default 0, Ashborn 10, Hatchling 100, Fledgling 110, Firewing 120, Flamecrest 130, Sunfeather 140, Pyrelord 150, Immortal 160, won ranks 115 / 135 / 155 (just above the tier they copy), builder 600, helper 700, mod 800, admin 900, owner 999. Staff always show above donors, a staff member who also bought a rank shows the staff badge, and every weight above 0 is exempt from lockdown (460).
- **Groups.** Each donor group has the one below as parent (`lp group fledgling parent add hatchling`, hatchling parent ashborn); a purchase removes the lower donor group so the badge is right. Won groups copy a tier by `parent add` of that donor group and have their own weight, colour and look line. All of this is in `server/permissions/ranks.txt` (new module file, applied after `base.txt`).
- **Account-wide (PR3, RTA-6).** A rank works on every profile and never expires; vault contents and kits are per profile; nothing moves between profiles.
- **Chargeback (C1-R1-35, C1-R2-18).** The rank is removed and the account flagged by the credit chargeback command; the rank row keeps the order id.

## What the player sees

## Rules and limits
- **Cap (RK-CAP, stricter after R3-7):** a bought rank never changes money, drops, crystals, island progress, PvP or skill XP. No island or pillar XP from ranks (RTA-20).
- **Mojang (principle 8):** ranks sell looks and convenience only. The check of the current usage guidelines before the store opens still stands (RTA-1, I6).
- `/ec` and `/craft` are blocked in the warzone, boss arena and 10 s after combat. Nicknames: 3 to 16 letters, reserved words blocked, 60 s between changes, reset when the rank is lost.
- Bedrock: prefixes are short, rank menus are click-only. Performance: perks are permission nodes read when used; the tab list reads LuckPerms off the main thread.

## Developer decisions (defaults; the owner only vetoes)
- **Colours.** Exact hex above; `RankLooks` gets `bold()` from `&l`; `RankConsistencyTest` reads `base.txt` and `ranks.txt` against the default looks (hex equal, prefix code equal) and checks that every pair of single-colour looks is at least 30 apart in Lab. Bedrock uses the nearest classic code; a phone check by the owner.
- **Permissions in files.** New `server/permissions/ranks.txt` creates groups, weights, parents, display names, `meta` colour, prefix and every perk grant; every `skyblock.*` node it grants is declared by its owner module (`PermissionFilesTest`). New nodes `skyblock.join.full`, `skyblock.pv.<n>`, `skyblock.rank.kit` are declared in the owning module's `permissions/*.yml`.
- **Delivery.** `CreditShop.buy()` grants a rank by console `lp user <name> parent add <group>` plus removal of the lower donor group, idempotent by order id, retried by the order queue; audit row with order id. Won ranks: the season service adds and removes the groups; the winners list is shown to an admin first.
- **Migration.** Existing `ember` members keep their group; `default` display name becomes `New` (gray, no badge text confusion) when EP-Q15 is accepted; weights renumbered in one apply run: `meta removeprefix <old priority>` first, then new prefixes.
- **Tests.** Look parsing, bold, consistency, weight order (staff above won above donors above free above default), perk table numbers monotone per tier, `RankPerks` best-of rule for bought plus won, upgrade price arithmetic (target minus owned), idempotent grant.
- **Config.** Look lines in `chat.yml`; perk numbers in `perks.yml` (`ranks.<group>.*`) read by one `RankPerks` service; texts in `messages/perks.yml`.
- **Bedrock.** Badge text at most 12 characters including brackets; rank menus are click only.
