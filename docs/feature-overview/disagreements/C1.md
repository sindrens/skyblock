## E. Risks found in the code (not on the card)
1. Island-member exception lets an alt invited to the main's island `/pay` its start money ($1,000) and rewards (about $2,500 tutorial) to the main with no $10k earned. Small per alt, scales with alt count. (`EconomyModule.java:233-245`, `SendGateImpl.java:48-53`)
2. Orphaned balances on profile delete: `onProfileDeleted` only zeroes the personal bank; the purse, crystals and shards stay in `eco_accounts`, count in the supply snapshot and baltop (`EconomyModule.java:287-300`). A profile-keyed gem payout to a deleted profile lands in an unreachable account (`EconomyServiceImpl.normalize :142-148`).
3. Gems are not in the alert currencies and are not frozen (see C).
4. Hard-coded values: `Amounts.EXACT_BELOW = 100_000`, `BALTOP_CHECK_TICKS = 100`, retry counts, note purge timings, English tab-hint strings `NOTE_REASONS`/`STAFF_REASONS`, a 3 s /pay cooldown default.
5. `CHECK (balance >= 0)` (`V001__economy.sql`) means a chargeback cannot take back credits that were already spent.

## F. Confirmed as matching
Four currencies and the enum; atomic debit/credit with `WHERE balance >= ?`, overflow guard and ledger row with before/after balances and unique `idem_key`; whole-number amounts with `k/m/b/t/q` suffix parsing; `tradeable.*` defaults; start balances $1,000 and 0; account-wide gems and per-profile rest; tab completion on /bal /baltop /pay /withdraw /eco /trade; booster thanks 1 gem, cap 100, no payment on same IP; tutorial reward $2,500 + 25 crystals + 5 per optional step; Conqueror crate 15% for 5 shards; profile slots 500 / 1,500; wardrobe gem sets 400 / 900; crystal drop chance 0.05 at tier 1 rising by x1.3 per tier (0.896 at tier 12); enchant step cost 100 x1.8 (for rare enchants); Deepforge 25,000 crystals; no blocking DB calls on the main thread.
