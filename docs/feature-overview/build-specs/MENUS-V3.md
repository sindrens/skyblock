## 0. Goal and scope
**Goal:** the menus follow one FORMAT: one wallet tile where money is spent, centred groups, a podium board, a grouped shop grid, short tooltips with hard limits. Concretely: (A) framework helpers and a ratchet test for the limits, (B) the island hub on 4 rows with 12 tiles in four groups and a synergy line on every tile, (C) `/is top` as podium + places 4-10 + you (and `/menu` Top aligned to it), (D) the shop: grouped item grid, category order, one-hint tooltips, wallet tile and the live-file migration to config-version 3 (the shop **contents** are the ECON lane's, `ECON-TABLES.md` D, ledger `ECON-R1-08`).
**Out of scope:** the upgrade/masteries mastery tree (another spec; only its slot and panel type are reserved, section 7), Members/Level/Upgrade/Masteries layouts of B3/B13/B14, shop prices (C15), **which items the shop sells (ECON lane, `ECON-TABLES.md` D: remove 53, add 46, 255 items, `price: auto`, spawners tab 20 mobs)**, the Spawners tab v2 (D2, unlocked), the font itself (GUI-FONT), the remaining ~170 menus (rollout list, section 9).

## 2. Decisions made in this spec (developer decisions; the owner only vetoes)
| # | Decision | Why |
|---|---|---|
| D1 | Hub tiles keep fixed slots; a hidden tile (feature not built) leaves its slot empty, groups are not re-centred | muscle memory; no layout shift between servers |
| D2 | Buy and sell GUIs (`P3`) keep the item on slot 4 and show no balance line; `\| You can afford: N` is the only money hint. The wallet tile lives on the category menu and the grid | slot 4 cannot hold both; FORMAT says no balance in every tooltip |
| D3 | `/is top` has no Season tab: there is no season board store (`IslandTop.Kind` has LEVEL, VALUE, WEEKLY_GAIN, WEEKLY_PILLARS). The Weekly tab exists already | "only if cheap": a season store is not cheap |
| D4 | Shop contents are **not** decided in this spec: single source `ECON-TABLES.md` D (ledger `ECON-R1-08`). Section 6.1 lists the review notes found while building the group plan | two lanes must not give two different lists |
| D5 | Even split of a group longer than 7: `rows = ceil(n / 7)`, sizes as equal as possible, larger rows first (16 = 6 + 5 + 5, 9 = 5 + 4, 12 = 6 + 6, 15 = 5 + 5 + 5). C5's plan wrote "16 = 8 + 8", which cannot fit a 7-wide grid | arithmetic |
| D6 | One Java hint line on shop tiles, chosen by priority (`Right-click: sell` if sellable, else `Shift-click: buy a stack`); the `· Left-click` / `· Right-click` suffixes and the second hint go | owner V3-Q15 a ("one Java hint"), FORMAT limit 7 lines |
| D7 | Format limits are enforced by a **ratchet** test (known violations in a baseline file may only shrink); new violations fail the build | owner V3-Q16 a; a hard test over 190 menus on day one would block everything |

## 3. (A) Framework changes, `common/.../menu`
| Change | Detail |
|---|---|
| `Centered.split(int n)` | row sizes of a group of `n` (1..28+): `rows = ceil(n/7)`, sizes equal, larger first; `n <= 7` gives `{n}` |
| `Centered.gridColumns(int count)` | columns (1..7) of a row of `count` (1..7) in the 7-wide grid: 1 `{4}`, 2 `{3,5}`, 3 `{3,4,5}`, 4 `{2,3,5,6}`, 5 `{2..6}`, 6 `{1,2,3,5,6,7}`, 7 `{1..7}` |
| `Centered.grid(int... rowCounts)` | slots of sequential rows starting at screen row 1 (`9 * (row + 1) + column`), one row per count; `gridFrom(int firstRow, int... counts)` for a start row. Throws above 4 rows or above 7 per row |
| `PageLayout<T>` (new interface) | `List<Page<T>> pages(List<T> entries)`; `record Page<T>(List<T> entries, int[] slots)`; `static <T> PageLayout<T> grid()` = today's behaviour (28 per page, `CONTENT_SLOTS` left to right, via `Pagination`) |
| `PagedMenu` | new overridable `protected PageLayout<T> pageLayout()` (default `grid()`); `title()` and `build()` use the layout's pages (page count, slots per entry); everything else unchanged (nav bar, arrows with the target page as count, empty state). `PagedMenu` subclasses that do not override it behave exactly as before |
| `PodiumPages<T>` (new, implements `PageLayout`) | page 1 = the first 10 entries on slots `13, 21, 23, 28..34`; page 2 and later = 18 entries centred with `Centered.split(18)` = rows 6 + 6 + 6 on screen rows 1-3. Used by both Top menus |
| `MenuLayout` | `previous(3) = 25`, `next(3) = 26` (3-row page buttons, FORMAT 3.1); `search` stays 6 rows only; javadoc table updated |
| Wallet tile | `MenuService#wallet(Player viewer, String currencyKey, String amountText, String noteKey)` returns a display-only `MenuButton`: icon `currency/<key>` (`money`, `crystals`, `shards`, `credits`), name `wallet.<key>.name` (currency colour, bold: `Your Money`), lore the full amount (`wallet.<key>.amount`) and an optional muted note line. `Menu#setWallet(String currencyKey, String amountText, String noteKey)` puts it on `SLOT_SUMMARY` (4). Texts in `plugin/.../messages/menus.yml`: `wallet.money.name: "<cur:money><bold>Your Money"`, `wallet.money.amount: "<cur:money><amount>"`, same for `crystals`, `shards`, `credits` (`Your Crystals`, `Your Shards`, `Your Credits`) and `wallet.bank.name: "<cur:money><bold>Island Bank"`. Amounts are full with separators (`$1,250,000`), credits always exact |
| Plaque nouns | `Menu#plaqueKey()` hook is GUI-FONT's; this spec only adds the message keys named in sections 4-6 |
| `FormatLimits` (new, pure test helper in `plugin/src/test/java/net/skybornmc/skyblock/`) | `visibleLength(String miniMessage)`: removes style tags (`c:`, `cur:`, `area:`, `tag:`, `bold`, `/..`, `gradient`, hex), `<sym:x>` = 1 character, every other `<placeholder>` = 6 characters; `lines(...)`, `actionLineLast(...)`, `sections(...)` |
| `TooltipFormatAuditTest` (ratchet) | for every bundled messages file under `plugin/`, `modules/*/src/main/resources/messages/`: for each `*.lore` list (with its sibling `*.name`): at most 5 lore lines, at most 36 visible characters per line, at most one `» CLICK` line and it is the last line, no italics tag, no `<#hex>` or raw colour name (tokens only). Violations are compared with `plugin/src/test/resources/format-baseline.txt` (one `file:key:rule` per line). A violation not in the baseline fails the build; set env `FORMAT_BASELINE_WRITE=1` once to create the first baseline; the file only ever shrinks as menus are migrated |
Docs: `docs/UI_STYLE.md` section 5 and 6 point to FORMAT; `docs/FORMAT.md` section 3.1 notes `previous(3)`/`next(3)`.

### 6.3 Live migration to config-version 3 (`ShopCatalogMigration`, data-driven)
The live `shop.yml` is a v2 file and "a deleted entry comes back", so changing the bundled list alone changes nothing on the server. One migration moves the live file to whatever the bundled v3 file says, so it needs no item list of its own (it works for the ECON lists and any later edit).
- Freeze today's bundled file as `modules/shop/src/main/resources/migrations/shop-v2.yml`. Constants `V2 = 2`, `V3 = 3`; `version(live) < 2` runs the existing v1 -> v2 code **with the frozen v2 file as its "bundled" argument** (so the old tests keep proving what they proved); `version(live) < 3` runs new `migrateV3(live, bundledV3, v2Defaults)`.
- `migrateV3` starts from the bundled v3 (tab order, `groups:`, comments). Items the live file has keep the live entry (price, `enabled`, `requires`, own `contains`) through `merge`. Items in `shop-v2.yml` that the bundled v3 lacks go to `worth-only` with their live price (log line `removed X (was $p in tab); its price stays only as block worth`). Items new in v3 are added exactly as the bundled entry (a `price: auto` value is copied verbatim, never compared as a number); a new item that sits in the live `worth-only` leaves it. Owner-added items stay in their tab. Live `worth-only` entries are copied unless the id is sold again. `config-version: 3`.
- `ShopModule#loadCatalog`: backup `shop.yml.before-v3` (first time), `shop-migration-v3.log`, console lines, audit `shop_catalog_migrate` with `version: 3` (same helper as v2). `addMissing` runs afterwards and never re-adds a parked item. Old files without `groups:` keep working (flat order).

| Risk | Mitigation |
|---|---|
| The ECON removals (53) upset players or break a tutorial/quest that names an item (HT-Q12: the new tutorial shop-buy step needs one item that stays sold) | the migration only parks items under `worth-only` (reversible); before the build the coder greps `modules/tutorial`, `modules/quests`, `modules/rewards` configs for removed ids and reports them to the owner |

| Island level changes because items left the shop | `worth-only` keeps the price, `ShopCatalog#worth` is unchanged; `ShopCatalogMigrationV3Test` |
| The ratchet baseline hides real problems | it only shrinks; the number is printed in the test output; each menu migration deletes its lines |
| `PagedMenu` generalisation breaks the 14+ other paged menus | default layout is the old behaviour; `PagedMenuLayoutTest` |
| Hub tile text longer than 36 characters after translation of placeholders | `IslandHubTextTest` counts placeholders as 6 |
