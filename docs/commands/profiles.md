# Profiles module (`modules/profiles`): PROF

Island profiles (owner decisions P1–P12 and round 3 PR1–PR5, `docs/DECISIONS_2026-10-30.md`). A player has up to 3 profiles; a profile is one island and everything that belongs to it. Settings: `profiles.yml`; texts: `messages/profiles.yml`; data: tables `profiles`, `profile_accounts`, `profile_states`, `profile_slots`.

## Per profile vs. shared
- **Per profile** (stored under the profile key): money, crystals, shards, inventory + armor + offhand, ender chest, XP levels, health/food/effects, skills, Depths tier unlocks, island membership/role/coop trust, start money (owner answer 121: every profile gets it, once per season), auction listings + collection bin, money notes created, `/settings` values (keys in `settings.profile-keys`), playtime. Future: satchel, personal bank, quests/battle pass, achievements, tools (items follow the inventory).
- **Shared** (stored under the player UUID): credits, rank, titles/tags (achievement titles become account titles), cosmetics, nickname, punishments, island join limits (P11), likes/ratings, island bans, the audit identity, staff homes, vanish.

## Switching
Save the current state (inventory, armor, offhand, ender chest, XP, health, food, effects, location) and make the target active in **one** database transaction, then load the target's state and teleport to its island home (spawn when it has no island). While the switch runs the player can't drop, pick up, click, use, build, run commands or take damage. Refused: in combat/boss arena (modules cancel `ProfileSwitchEvent`; `switch.blocked-worlds`), while frozen or in staff mode (staff module), while dead, with an item on the cursor, to a profile whose slot is locked. Anti-spam: `switch.cooldown-seconds` (10; bypass `skyblock.cooldown.bypass`). Crash safety: the active profile's state lives in the player file; a saved state row of the active profile means "not applied yet" and is applied on the next join; a player whose switch is still saving can't log in for that moment. If the database takes longer than `switch.timeout-seconds` (10) the player is kicked (their file equals the saved state because they were locked) and the next join applies whatever the database decided; a profile state that fails to load also kicks instead of playing on with half an inventory. New items for a profile (auction deliveries, notes) never land in an inventory while its player switches.

## Slots (P6, P8, PR5)
Slot 1 free. Slot 2: `slots.price-2` credits (500) or `skyblock.profiles.slots.2` (Knight+). Slot 3: `slots.price-3` credits (1,500) or `skyblock.profiles.slots.3` (Warlord+). Slots are independent. Credit payment (earned first, then bought): ledger reason `profile_slot`, idempotency key `profile_slot:<player>:<slot>` (paid once ever). Stored unlocks keep their source (`credits`, `grant`; old `gems` rows were renamed by `db/profiles/V002`); a season reset keeps only `credits` (`ProfileServiceImpl#seasonReset`, called by the season module later). A profile whose slot is locked again (rank lost) stays, but you can't switch to it (you can delete it).

## No transfers between own profiles (P3, P4)
`ProfileService#blockOwnTransfer` refuses and audits `profile_transfer_blocked` (details: path, from/to profile) on: `/pay`, auction buy, money note redeem, island invite accept/coop/join, item pickup of items dropped or thrown (tridents/arrows) by another own profile. Islands: another own profile's island can't be joined, cooped or visited.

Owner answer 118: deleting a profile deletes everything on it (money, skills, auction listings and collection bin, its solo island); only account-wide data stays. A profile that leads a team island with other members still can't be deleted (answer 117). Daily login rewards and streaks will be per profile (answer 128) once a daily reward exists. The first profile of every account uses the **player UUID as its key**, so all data from before profiles is profile 1 with no data moved; later profiles get random UUIDs and a deleted key is never reused.

## Island = profile (owner 4 Nov 2026)
A profile **is** one island membership. **Every way of leaving the island wipes the profile**: `/is leave` (and the Leave button), a kick, a staff/moderation removal, a disband, a staff island delete or reset, replacing your solo island to accept an invite, and `/profiles reset`. Coop is not membership and never wipes.

- **Wiped:** money, crystals, shards, personal bank, inventory + armor + offhand, ender chest, XP, health/food/effects, island tools and tools, skills, quests and island tasks, collection, milestones, storages, wardrobe, crate keys, personal boosters, auction listings, money notes, profile settings, profile playtime, the /farm and /mine tier (`state.persistent-keys`), island membership and homes. **Kept:** credits, rank and permissions, store purchases, achievements (moved to the fresh profile), cosmetics, tags/titles, nickname, account playtime, punishments, profile slots (`common/profile/WipeScope`).
- **How:** the profile key is *retired* (marked deleted, every module's rows stay untouched) and the slot gets a fresh key. Everything stored per profile is therefore empty in every module at once; account data stays. A player online on that profile switches to the fresh one at once (a normal `ProfileSwitchedEvent`), gets a chat summary (money, shards, items lost; what stays) and then the start flow gives the fresh profile its island. An offline player is wiped in the database right away; their player file still holds the items, so the next join saves them into the snapshot first (`profile_captures`) and only then empties the inventory. They get the summary on that join.
- **Snapshot:** the retired key + its saved state, listed in `profile_snapshots`, kept `wipe.snapshot-days` (14). `/profiles restore` puts it back. After the retention the purge (`wipe.purge-interval-minutes`) fires `ProfileDeletedEvent` for the old key and every module deletes its rows.
- **Crash safety:** islands save a wipe intent (`profile_wipe_intents`) before the removal and wipe after it. A leftover intent (crash in between) is finished by the sweep (`wipe.intent-sweep-seconds`) when the profile is no longer on that island, or dropped when it still is. The wipe itself is one transaction; the in-game part follows the switch rules (locked player, kick on timeout, pending state applied on the next join).
- **Joining needs an empty profile:** a profile without an island joins at once; alone on your own island, accepting replaces it (confirm screen with the losses, wipes this profile); on an island with others: "Use an empty profile slot or leave your island first" with `[Profiles]` and `[Leave]`. Pending invites follow the person to the fresh profile.
- **Anti-abuse:** `profile_wipe_pay_flag` (economy audit) when the wiped profile sent at least `economy.yml pay.leave-flag.amount` (100,000) with `/pay` in the last `pay.leave-flag.minutes` (10).
- **For other modules:** `ProfileService#supportsWipe`, `intendWipe`, `wipe`, `dropWipeIntent`; events `ProfileWipedEvent` (carry account data kept under the profile key, move references that follow the person) and `ProfileRestoredEvent` (carry it back). Modules never delete on a wipe: that happens at the purge through `ProfileDeletedEvent`.

Audit (category `auth`): `profile_wipe`, `profile_wipe_items_taken`, `profile_restore`, `profile_snapshot_purge`; economy: `profile_wipe_pay_flag`; achievements: `achievements_profile_carried`.
