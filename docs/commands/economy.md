# Economy (`modules/economy`)

Currencies: Money, Crystals (island crystals, replaced tokens; not tradeable), Gems, Shards (whole-unit `long`). Every change is one atomic database transaction with a ledger row (`eco_ledger`) and an audit row (category `economy`, action = reason), so `/logs pay <player> [other]` and `/logs player <name> economy` show it. Settings: `economy.yml`; texts: `messages/economy.yml`.

`/eco` is for admins and the owner (`skyblock.admin.economy`, granted to admin; owner decision #47). Every use is audited (ledger + `/logs`), alerts online staff and the console, and tells the player. The old node `skyblock.owner.economy` still works (it grants `skyblock.admin.economy`).

Other: `skyblock.staff.economy.alerts` (chat alert when staff use `/eco`; helpers and up).

**Sell multiplier cap.** `economy.yml → sell.multiplier-cap-percent` (default `300` = at most ×4.0, owner decision #46). Every sell bonus (rank, Sell Multiplier upgrade, sets, personal/global boosters, events) is added up and capped once. Sell code reads the cap with `EconomyService.sellBonusCapPercent()` and applies it with `MultiplierCap.apply(base, totalBonusPercent, cap)` (`common/economy`; rounds down, never overflows, never negative).

**Money notes (M3.2).** Right-click a note (main hand) to cash it; no permission needed. Each note is a row in `money_notes` (id = the item's unique id); the amount comes from that row, never from the item. Cashing locks the row, marks it `redeemed` and deposits in one database transaction (idempotency key per note), so a note can never be cashed twice: a copy is taken from the hand, staff with `skyblock.staff.notify` get an alert, and an audit row `note_dupe` is written (`/logs`). Notes can't be crafted with, sold to villagers or used in a cartography table, and can't be listed on the auction house (`auction.yml → items.allow-money-notes: false`). Audit actions: `note_withdraw`, `note_redeem`, `admin_note`, `note_dupe`, `note_return_failed`.

Placeholders (cached, for the HUD and other plugins via PlaceholderAPI): `balance`, `balance_formatted`, `crystals`, `crystals_formatted`, `gems`, `gems_formatted`, `shards`, `shards_formatted` (`_formatted` = `12,500` / `1.2M`, no symbol).

For developers: `core.services().optional(EconomyService.class)` (`common/economy`): `execute(Transaction)` with reasons from `TxReason`, a `reference` and an `idempotencyKey` for anything that can be replayed. Never decide with the cached balance; run the transaction and handle `INSUFFICIENT_FUNDS`.

## Profiles (PROF)
Money, crystals and shards belong to the active **profile**; gems belong to the player (owner P2/PR2). `/bal`, `/pay`, `/eco` and `/withdraw` use the active profile (offline players: their last active profile); gem changes always go to the player. `/baltop` shows each player's **best** profile (P7). `/transactions` shows the profile's history plus the player's gem history. `/pay` between two profiles of the same player and cashing a `/withdraw` note on another own profile are refused (`pay.own-profile`, `note.own-profile`) and audited (`profile_transfer_blocked`). A new profile gets no second start balance (one per player and season). A deleted profile's money, crystals and shards are set to 0 (ledger reason `profile_delete`). Gem purchases of profile slots use reason `profile_slot`.

## Selling (M3.4)
**Prices.** `sell.yml` holds the base price, category and on/off (`{ price: 82, sellable: false }`) of every sellable item; vanilla items by item id, custom items under `custom-items` by custom id (a custom item is never priced as the vanilla item it is made of). Defaults come from `docs/ECONOMY_BALANCE.md` (BAL2) and are a **draft the owner approves before launch**. Items not listed can't be sold. **Never sellable**, whatever `sell.yml` says: unique items (custom tools, enchant books, money notes, set pieces: anything with a unique item id), dupe-flagged items, `sell.blocked-ids` (`money_note`, `starter_*`, `tool_*`), items with a `sell.blocked-data-keys` key (starter kit), and custom items whose type is not in `sell.custom-types` (default: materials only).

**Dynamic prices** (`economy.yml → sell.dynamic.*`, ECONOMY_BALANCE §8): price = base × multiplier (floor 40%, ceiling 150%). Each item sold lowers the multiplier by an *impact*; inside one sale the price drops item by item, so splitting or bundling a sale pays the same. Every 10 min the gap to base closes by 2%; items without a sale for 60 min drift up +10% per day toward the ceiling. The impact is recomputed every hour from the rolling 24 h volume so a steadily sold item settles at 85% of base (default 1 ppm while there are fewer than 1,000 sales in 24 h; clamped 0.01–100 ppm). Steps, the hourly recompute and saving (`sell_prices`, every 5 min and on shutdown) run off the main thread; a restart applies the steps missed while the server was off (max 168 h). **Hot Item:** one item a day (Europe/Oslo date, picked from the date, `sell.hot-item.*`) sells for +25%; it changes the price, not the sell bonus. The menu shows the price per item, the trend over the last hour (Rising/Falling/Steady: words, the ▲▼ arrows are not Bedrock-safe) and the % from base.

**Sell bonus.** Every `BonusFamily.SELL` source of the `BonusService` (rank, island upgrades, sets, enchants such as Gilded Touch, boosters, events …) is added up and capped once at `EconomyService.sellBonusCapPercent()` (+300%), applied to the subtotal after dynamic prices. The menu lists each source and says when the cap cuts the total.

**Safety.** The sell box only remembers slots; every inventory click is blocked while it is open, so closing it, logging out or a crash can never lose items. On a sale the stacks are checked again, taken out on the main thread (escrow), the player's data is saved (`sell.save-player-data`, so a crash after the payment can't roll the inventory back to a state that still holds them), then **one** ledger transaction (reason `sell`, idempotency key `sell:<sale id>`) pays the active **profile** and writes the `sell_sales` record in the same database transaction. If it fails, every stack is handed back (inventory, else at the feet; if the player left or switched profile, stored in `sell_refunds` and handed back on the next join/switch to that profile, exactly once). The price drop is reserved before paying and given back on failure, so two sales at once can't both get the old price. Frozen players and players switching profile can't sell.

**Logs.** One ledger row and one audit row (category `economy`, action `sell`) **per sale**, never per stack; the audit row holds every item and amount, the line values and multipliers, the subtotal, the bonus and the source (`gui`, `hand`, `all`, later `satchel`, `afk`). `/logs player <name> economy`, `/transactions` (type "Selling").

For developers: `core.services().optional(SellService.class)` (`common/sell`): `price(stack)`, `price(key)`, `sellable(stack)`, `quote(stacks, bonus)`, `bonusPercent(player)`, and `sell(SellRequest)` for stacks the caller already removed (give back `SellResult.giveBack()` afterwards). Satchel (M4.4), AFK pool and auto-sell chests use this.

## Banks (M3.3)
`/bank` (and the island menu's **Bank** button) shows both banks. Settings: `bank.yml`; texts: `messages/economy.yml → bank.*`; data: `eco_accounts` (owner type `bank` = a profile's personal bank, `island` = an island bank), `eco_bank_state`, `eco_bank_withdrawn`, `eco_bank_activity`.

- **Personal bank:** one per **profile** (owner P2), only reachable from that profile (P4: no deposits to another own profile's bank; tried transfers are refused and audited `profile_transfer_blocked`). Kept when you leave or are kicked from an island. **10 tiers** (`personal.tiers`: capacity, unlock cost = 2% of capacity, payout cap; balance sheet §6.1). The next tier is bought in the tier menu (confirm screen; ledger reason `bank_tier`). Perks per tier: `messages/economy.yml → bank.perks.tier-N` (shown only; owner list pending, #45). A deleted profile's bank is set to 0 (`profile_delete`).
- **Island bank:** belongs to the island. Role permissions in `/is permissions`: **Bank deposit** (default Admin, Mod, Member), **Bank withdraw** (default Admin), **Bank history** (default Admin, Mod); the Leader always has all three, coop players and visitors never (REVIEW A4). Daily withdraw limit per role in % of the bank capacity (`island.withdraw-limit-percent.*`: Leader/Admin no limit, Mod 25%, Member 10%; Europe/Oslo day). Capacity by the Bank Capacity upgrade level, payout cap by the Bank Interest level (`island.levels`, §6.2; level 0 until Phase 5 upgrades exist). Online members see each deposit/withdrawal in chat. On `/is disband` or a reset what is left goes to the leader's balance (`bank_payout`, `island.pay-leader-on-disband`); a staff delete keeps it in the closed bank.
- **Interest** (`interest.*`): personal 0.15% / island 0.25% every 3 h, at fixed times, also offline. Paid on the **lowest balance during the period** (deposits count from the next period), capped per payout and by the free room, only when the profile (island: one member) played ≥ 2 h in the last 7 days (owner #38). Paid by a background run every 5 min (off the main thread, batches of 200) and when a bank is opened or used; each payout is one ledger transaction (`interest`) with the idempotency key `bank_interest:<account>:<period>`, so restarts or double runs never pay twice. After downtime at most 8 missed payouts are paid.
- **Withdrawals:** 2% fee (rounded up, leaves the economy, ledger `bank_fee`) and the current period's interest is lost; free in the first 10 minutes after each payout (`withdraw.free-minutes`). The confirm screen shows amount, fee and what you get. Deposit and withdrawal are each one ledger transaction (`bank_deposit`, `bank_withdraw` + `bank_fee` in the same atomic batch); capacity, bank balance and the daily island limit are checked inside that database transaction.

For developers: `core.services().optional(BankService.class)` (`common/economy`): `open`, `openIslandBank`, `personalTier`, `personalBalance`, `islandBalance`. Accounts: `AccountRef.bank(profileKey)`, `AccountRef.island(islandId)`. Island hooks: `IslandService.hasIslandPermission`, `bankCapacityLevel`, `bankInterestLevel`, `IslandRemovedEvent`.
