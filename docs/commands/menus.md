# Menus module (`modules/menus`): M1.6 + M1.7 + staff hub and `/admin` (M1.12)

Layout: `menu.yml` (hub), `help.yml` (help categories, topics, pages), `navigation.yml` (menu item), texts: `messages/navigation.yml`.

| Command | Description | Permission | Status |
|---|---|---|---|
| `/menu` (`/gui`) | Main hub: every feature; not-yet-built ones shown locked "Coming soon". Also the **menu item** (Nether Star, hotbar slot 9; any click/tap, "Menu · Click"). FIXES1: it always stays in the inventory (can't be dropped, moved, stored or lost on death; put back on join, respawn, world/game mode change, after closing any inventory and every `menu-item.check-seconds` (5)); paused while staff mode owns the hotbar or a profile switch runs; players can still turn it off in `/settings`. Root cause of the old "Removed 1 menu item(s) from X's inventory" log: it shared the GUI button key, so the menu framework's leak check deleted it on join and after every menu close; it has its own key now | `skyblock.menu` (everyone) | ✅ |
| `/help [topic\|category\|commands]` (`/guide`) | Help menu: categories, topics with pages, Take me there, Show in chat; command lists generated from the commands you may use. Console/chat gets the chat version. Every menu's "?" opens `/help <topic>` | `skyblock.help` (everyone) | ✅ |
| `/settings [setting] [on\|off\|toggle]` (`/options`, `/prefs`) | Personal settings menu (Chat, Social, Display, Sounds); chat form for quick changes, Tab lists them | `skyblock.settings` (everyone) | ✅ |
| `/staff` (`/staffmenu`) | Staff hub: Display, Config editor, Titles & Tags, staff tools (unbuilt ones "Coming soon") | `skyblock.staff.menu` | ✅ |
| `/admin` (`/config`) | Config editor generated from every module's typed config: toggle, cycle, number picker, chat input, list editor; validated, saved, applied live (or "needs restart"), logged `config/edit` old→new. database.yml hidden | `skyblock.admin.config`; owner-level settings `skyblock.owner.config` | ✅ |

Settings now (all apply instantly, no relog): **menu item**, **ui-sounds** (menus: every menu sound + `navigation.yml → settings.ui-sound-keys`, via `Sounds#playUi`) and **event-sounds** (menus: `Sounds#playEvent`, e.g. the Depths mini-boss spawn) are owned here; taken over by their modules through the `PlayerSettings` service: private-messages, afk-broadcast (social), mentions-sound, chat-colors, chat-timestamps (chat), join-messages, tpa-requests (essentials), scoreboard (hud), island-invites (islands), trade-requests (trade), particles (wardrobe: other players' set trails). Still "Coming soon" (no feature yet): tips, depths-visibility.

**Warps (UX3).** The hub's Warps button (built-in action `warps`, like `settings`/`help`; an old menu.yml with the `is warp` default is switched once) opens a small 6-row warps menu from `menu.yml → warps`: Spawn (`/spawn`), Market Square, Crate Yard, Forge Quarter, Tavern, Hall of Heroes (road entries of the applied builds), The Depths (The Gate, `/dungeon` warmup) and Player Warps (`/is warp`). Targets: `command <cmd>`, `point <category> <id>` (build-points.yml) or `location <world> <x> <y> <z> [yaw] [pitch]`; an entry whose place does not exist (build not applied, world not loaded, command missing) is hidden. One click closes the menu and teleports through the core TeleportService (`/spawn` warmup and cooldown unless `reason: dungeon`; guards such as locked Depths tiers explain themselves). Texts: `messages/navigation.yml → warps.*`. No new command.

**Menu titles (UX3).** A menu whose title text is missing or empty gets `menus.yml → title.fallback` (an empty chest title shows "Large Chest" on Bedrock). Clicking the menu item inside your own inventory closes the inventory and opens `/menu` `menu-item.inventory-open-delay-ticks` (3) later, so Geyser can show the title.

Permission definitions: `modules/menus/src/main/resources/permissions/menus.yml`. Rank grants: `server/permissions/menus.txt`.
`/admin` uses the plugin-level `skyblock.admin.config` / `skyblock.owner.config` (see [core](core.md)).
