# Menus module (`modules/menus`): M1.6 + M1.7 + staff hub and `/admin` (M1.12)

Layout: `menu.yml` (hub, You, Travel, /staff), `help.yml` (help categories, topics, pages), `navigation.yml` (menu item), texts: `messages/navigation.yml`.

| Command | Description | Permission | Status |
|---|---|---|---|
| `/menu` (`/gui`) | Main hub (GUI-2): your head (opens **You**) and 14 features in 4 groups (Play, Money, Power, More); features that are not built are hidden (`navigation.yml → hub.show-unbuilt: true` shows them as "Coming soon" on the test server); **Rewards** glows with the number ready and claims them in one click. Also the **menu item** (Nether Star, hotbar slot 9; any click/tap, "Menu · Click"). FIXES1: it always stays in the inventory (can't be dropped, moved, stored or lost on death; put back on join, respawn, world/game mode change, after closing any inventory and every `menu-item.check-seconds` (5)); paused while staff mode owns the hotbar or a profile switch runs; players can still turn it off in `/settings`. Root cause of the old "Removed 1 menu item(s) from X's inventory" log: it shared the GUI button key, so the menu framework's leak check deleted it on join and after every menu close; it has its own key now | `skyblock.menu` (everyone) | ✅ |
| `/help [topic\|category\|commands]` (`/guide`) | Help menu: categories, topics with pages, Take me there, Show in chat; command lists generated from the commands you may use. Console/chat gets the chat version. Every menu's "?" opens `/help <topic>` | `skyblock.help` (everyone) | ✅ |
| `/settings [setting] [on\|off\|toggle\|<choice>]` (`/options`, `/prefs`) | Personal settings menu (Chat, Social, Display, Sounds); chat form for quick changes, Tab lists them. | `/admin` (`/config`) | Config editor generated from every module's typed config: toggle, cycle, number picker, chat input, list editor; validated, saved, applied live (or "needs restart"), logged `config/edit` old→new. database.yml hidden | `skyblock.admin.config`; owner-level settings `skyblock.owner.config` | ✅ |

Settings now (all apply instantly, no relog): **menu item**, **ui-sounds** (menus: every menu sound + `navigation.yml → settings.ui-sound-keys`, via `Sounds#playUi`) and **event-sounds** (menus: `Sounds#playEvent`, e.g. the Depths mini-boss spawn) are owned here; taken over by their modules through the `PlayerSettings` service: private-messages, afk-broadcast (social), mentions-sound, chat-colors, chat-timestamps (chat), join-messages, tpa-requests (essentials), scoreboard (hud), island-invites (islands), trade-requests (trade), particles (wardrobe: other players' set trails). Still "Coming soon" (no feature yet): tips.

**Multiple-choice settings (VIS).** `SettingToggle.choice(...)` registers a setting with named choices instead of on/off (`PlayerSettings#choice`, `#setChoice`, `#onChoiceChange`; stored like switches, only when different from the default). In the menu it is one button with the setting's icon: the lore lists every choice with the current one ticked (`settings.choice-selected` / `settings.choice-other`), one click moves to the next choice (Bedrock-safe, no typing). Texts: `<textKey>.name`, `.lore`, `.choices.<choice>`. The first one is **Show players** (Display row, spyglass, id `show-players`, owned by the core visibility service; see [core](core.md)): Everyone / Friends + island / Nobody. It replaced the old "Players in The Depths" placeholder.

**Clean hub, You and Travel (GUI-2, GUI_DESIGN §7.1-7.3, owner G1/G2/G6/G7/U1).** `/menu` has 15 buttons from `menu.yml → hub`: 4 your head (name, rank, money, crystals, playtime; click = You menu), Play 10 Home (`is home`) · 12 Island · 14 The Depths · 16 Travel, Money 19 Sell · 21 Shop · 23 Bank · 25 Auction House, Power 28 Forge · 30 Skills · 32 Enchanter · 34 Wardrobe, More 39 Rewards · 41 Top (`is top`); each group has a coloured pane on the left edge of its row (`hub-groups`), the rest of the inside is dark space. Bottom bar from the framework: 48 ?, 49 Close, 50 Help & guides (the only Help button). A button shows when `show` is on, its `service` is registered and its command exists; otherwise it is hidden (owner G2). One button per action (duplicates are skipped with a warning). Every screen opened from the hub has Back to it (U1).
- **You** (3 rows, `menu.yml → you`): 4 head, 10 Profiles, 11 Titles & Tags, 12 Achievements, 13 Settings, 14 Store (owner G6), 15 Rules & links; 18 Back, 22 Close.
- **Travel** (3 rows, `menu.yml → travel`, replaces the UX3 warps menu): 10 Spawn, 11 My Island (`is home`), 12 Depths Gate (`/dungeon` warmup), 13 Crate Yard, 14 Market, 15 Forge Quarter, 16 Visit Islands (`is visit` browser, Back returns to Travel); 18 Back, 22 Close. Targets: `command <cmd>`, `point <category> <id>` (build-points.yml) or `location <world> <x> <y> <z> [yaw] [pitch]`; a place that does not exist (build not applied, world not loaded, command missing) is hidden. Teleports go through the core TeleportService (warmup, cooldown, Depths tier guards).
- **Rewards** (owner G7): the `RewardsService` (common, implemented by the rewards module) counts what is ready; the button glows gold with that count. One click claims everything ready through the rewards module's crash-safe claim (today: the daily reward; playtime rewards pay by themselves, the summary line says so; votes later) and shows one line. With nothing ready it opens `/daily`.
- **Migration:** a live `menu.yml` with the old `entries` (28 buttons) and `warps` is switched once at startup: old sections removed, the targets of Spawn, Market, Crate Yard, Forge and Depths carried into `travel`, the old file kept as `menu.yml.before-gui2`. No new command.

**Menu titles (UX3).** A menu whose title text is missing or empty gets `menus.yml → title.fallback` (an empty chest title shows "Large Chest" on Bedrock). Clicking the menu item inside your own inventory closes the inventory and opens `/menu` `menu-item.inventory-open-delay-ticks` (3) later, so Geyser can show the title.

Permission definitions: `modules/menus/src/main/resources/permissions/menus.yml`. Rank grants: `server/permissions/menus.txt`.
`/admin` uses the plugin-level `skyblock.admin.config` / `skyblock.owner.config` (see [core](core.md)).
