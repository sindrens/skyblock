# Wardrobe module (`modules/wardrobe`): W1

The wardrobe (docs/plans/WARDROBE.md): all 16 sets, per-profile wardrobe entries shown as locked real armor, the Wardrobe Chest, buying with money / crystals / gems (account Sigils), Set Tokens and set bonuses. Settings: `wardrobe.yml` (set levels switch, equip cooldown and blocked worlds, armor points per tier, chest size, token look, tier gates); set definitions: `sets.yml` (written from the jar on first start, new sets are added on updates; turn one off with `enabled: false`); texts: `messages/wardrobe.yml`; data: tables `wardrobe_sets`, `wardrobe_pieces`, `wardrobe_equipped`, `wardrobe_storage`, `wardrobe_sigils`, `wardrobe_claims`, `set_tokens`.

| Command | Description | Permission | Status |
|---|---|---|---|
| `/wardrobe` (alias `/sets`) | The wardrobe: **all sets** grouped by activity (owned first; filter All / Owned / Mining / Foraging / Farming / Combat / Fishing / Conquest / Other), each with its lock, price or pieces worn; **set screen**: wear or take off single pieces, Wear all / Take all off, bonuses, Buy (3-row confirm) / Claim / Redeem token; **Worn now** (active bonuses, "capped" when a family cap cuts them); **Wardrobe Chest** (store / take unique items). Click-only, Bedrock-safe | `skyblock.wardrobe` (everyone) | ✅ |

Rules (defaults, all in `wardrobe.yml` / `sets.yml`):
- Sets are database rows per **profile** (P2). Wearing puts real armor on (vanilla look: material, leather dye, armor trim; armor points by tier as attribute modifiers) that is only a view of the row: it can't be clicked, dragged, number-keyed, swapped, dropped, put in a container, armor stand, item frame or dispenser; worn pieces are taken off only in `/wardrobe`. Any piece found elsewhere (or with an old nonce, or from another profile) is deleted and audited; staff are told when it was outside the armor slots. Missing worn pieces are re-created. Vanilla armor in a slot moves to the inventory (refused when the inventory is full). Equip/unequip: 2 s cooldown, not in `equip.blocked-worlds` (warzone), not during a profile switch.
- Profile switch: pieces are taken off before the profile's inventory is saved and the new profile's pieces are put on after the load. Nothing in the wardrobe moves between profiles (P4); the chest and sets belong to the profile.
- Getting sets: tier I money sets $20k, Banneret $2.5M, Coinmaster $40M, Deepforge / Cropwarden / Dreadguard ◆ 25,000, Lorekeeper ✦ 400, Thornward / Stormkeel ✦ 900, Voidforged / Conqueror / Phoenix only from crates as Set Tokens. Gates: Depths tier per wing (from skill levels, `tiers.*`) or skill levels. Every purchase confirms, goes through the economy's guarded transaction (row + payment commit together, idempotency key `wardrobe_buy:<entry>`), one copy per set per profile, no refunds.
- Gem sets: buying one buys an account-wide **Sigil**; every profile can claim the set for free once per season (`season-id`); Sigils are kept across seasons.
- Set Tokens: unique items (one row each), tradeable and listable until redeemed (right-click or Redeem in the set screen; needs the gate and a profile that doesn't own the set). A token whose row is used up is a copy and is taken (staff told). Tokens can't be placed, crafted, renamed or dispensed.
- Wardrobe Chest: unique tracked items only (custom tools, enchant books, Disenchant Scrolls, Set Tokens, tomes later), 27 + 9 per storage grant (`skyblock.wardrobe.storage.1-3`). Escrow like the auction house: the database decides first while the inventory is locked; crash recovery on join gives back items left "releasing" and removes inventory copies of items that are in the chest.
- Bonuses: 2 and 4 pieces per set (merged entries count for both sets, the lowest level sets the multiplier), reported to the `BonusService` as source `wardrobe`; family caps apply once (sell: the economy's +300%). New families: crop growth (+100%) and conquest (+60% per stat), caps in `enchanter.yml → caps.*`. Set levels are off in W1 (`levels.enabled: false`): every set gives its 1× values. Sets with `enabled-from: conquest|fishing` show "Arrives with …" until `features.available` lists the feature.

Staff (no new command, WD25): **Wardrobe** button in `/inspect <player>`: their sets and chest size (`skyblock.wardrobe.staff`, helper+); admins (`skyblock.wardrobe.admin`) give a set, give a Set Token (player online) or remove a set, each with a confirm. Staff test commands (`/wardrobe admin …`) are not built (need owner approval).

For other modules: `core.services().optional(WardrobeService.class)` (`common/wardrobe`): `wornPieces`, `ownedSets`, `setLevel`, `setXp` (W2), `enchantSlots` (E5), `isSetPiece`, `createToken(set, origin, owner, actor)` for crates, `openStaffView`.

Audit (`item` unless noted): `wardrobe_buy`, `wardrobe_claim`, `wardrobe_token_created`, `wardrobe_token_redeem`, `wardrobe_token_confiscated`, `wardrobe_equip`, `wardrobe_unequip`, `wardrobe_stale_piece`, `wardrobe_store`, `wardrobe_take`, `wardrobe_take_recovered`, `wardrobe_stale_copy`; staff: `wardrobe_view`, `wardrobe_set_given`, `wardrobe_set_removed`, `wardrobe_token_given`; economy ledger reason `wardrobe_buy`.
