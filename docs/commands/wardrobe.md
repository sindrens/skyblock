# Wardrobe module (`modules/wardrobe`): W1 + W2 + W3

The wardrobe (docs/plans/WARDROBE.md): all 16 sets, per-profile wardrobe entries shown as locked real armor, the Wardrobe Chest, buying with money / crystals / gems (account Sigils), Set Tokens and set bonuses. Settings: `wardrobe.yml` (set levels switch, equip cooldown and blocked worlds, armor points per tier, chest size, token look, tier gates); set definitions: `sets.yml` (written from the jar on first start, new sets are added on updates; turn one off with `enabled: false`); texts: `messages/wardrobe.yml`; data: tables `wardrobe_sets`, `wardrobe_pieces`, `wardrobe_equipped`, `wardrobe_storage`, `wardrobe_sigils`, `wardrobe_claims`, `set_tokens`, `wardrobe_merges`, `wardrobe_tomes` (W2), `loadouts`, `loadout_slots_bought` (W3).

Rules (defaults, all in `wardrobe.yml` / `sets.yml`):
- Sets are database rows per **profile** (P2). Wearing puts real armor on (vanilla look: material, leather dye, armor trim; armor points by tier as attribute modifiers) that is only a view of the row: it can't be clicked, dragged, number-keyed, swapped, dropped, put in a container, armor stand, item frame or dispenser; worn pieces are taken off only in `/wardrobe`. Any piece found elsewhere (or with an old nonce, or from another profile) is deleted and audited; staff are told when it was outside the armor slots. Missing worn pieces are re-created. Vanilla armor in a slot moves to the inventory (refused when the inventory is full). Equip/unequip: 2 s cooldown, not in `equip.blocked-worlds` (warzone), not during a profile switch.
- Profile switch: pieces are taken off before the profile's inventory is saved and the new profile's pieces are put on after the load. Nothing in the wardrobe moves between profiles (P4); the chest and sets belong to the profile.
- Getting sets: tier I money sets $20k, Banneret $2.5M, Coinmaster $40M, Deepforge / Cropwarden / Dreadguard ◆ 25,000, Lorekeeper ✦ 400, Thornward / Stormkeel ✦ 900, Voidforged / Conqueror / Phoenix only from crates as Set Tokens. Gates: Depths tier per wing (from skill levels, `tiers.*`) or skill levels. Every purchase confirms, goes through the economy's guarded transaction (row + payment commit together, idempotency key `wardrobe_buy:<entry>`), one copy per set per profile, no refunds.
- Gem sets: buying one buys an account-wide **Sigil**; every profile can claim the set for free once per season (`season-id`); Sigils are kept across seasons.
- Set Tokens: unique items (one row each), tradeable and listable until redeemed (right-click or Redeem in the set screen; needs the gate and a profile that doesn't own the set). A token whose row is used up is a copy and is taken (staff told). Tokens can't be placed, crafted, renamed or dispensed.
- Wardrobe Chest: unique tracked items only (custom tools, enchant books, Disenchant Scrolls, Set Tokens, tomes later), 27 + 9 per storage grant (`skyblock.wardrobe.storage.1-3`). Escrow like the auction house: the database decides first while the inventory is locked; crash recovery on join gives back items left "releasing" and removes inventory copies of items that are in the chest.
- Bonuses: 2 and 4 pieces per set (merged entries count for both sets, the lowest level sets the multiplier), reported to the `BonusService` as source `wardrobe`; family caps apply once (sell: the economy's +300%). New families: crop growth (+100%) and conquest (+60% per stat), caps in `enchanter.yml → caps.*`. Set levels (W2) scale every bonus: Lv 0 = 0×, Lv 25 = 1×, Lv 50 = 2× (`levels.*`; off = `levels.fixed-multiplier`). Sets with `enabled-from: conquest|fishing` show "Arrives with …" until `features.available` lists the feature.

Set levels, tomes, merging, warzone (W2; defaults, all in `wardrobe.yml`):
- **Set XP** comes from the activity the set boosts while you wear **2+ pieces** of it (2-3 pieces 50%, 4 pieces 100%): Depths ore 1 / log 1 (the skills module's XP events), Depths mob kill 8 (only in `xp.combat-worlds`), island generator block 0.25 and log of a tree that grew 0.25 (only blocks the generator made or trees that grew; placed blocks never count), fully grown crop 0.5 (with a hoe), fish 25 (once `fishing` is in `features.available`). Stacked island mobs give none. Selling (1 per item, Coinmaster, max 8,000/h), bosses, KOTH, envoys and warzone kills arrive through `WardrobeService#setXp` when those modules send them. Lorekeeper earns 75% of every skill, Voidforged mining/foraging/farming, Phoenix everything except selling and warzone kills (`xp.sources.*`). Hourly caps: `xp.hourly-caps` (sell 8,000, farming 10,000).
- **Curve**: level L → L+1 costs 200 × 1.10^L (232,782 XP to Lv 50); merged sets need 1.5×. Level-ups play a sound and show the action bar; Lv 10/25/40/50 show a title. Lv 10 upgrades the trim material, Lv 25 = 1× (2nd enchant slot for E5), Lv 50 = 2×, glint on every piece, a particle trail (toggle in `/settings` → Display or the set screen; off in the warzone and while vanished) and the set can be merged. Earned XP is saved every 30 s, on quit, profile switch, merge and shutdown.
- **Wardrobe Tomes**: unique items (crates/quests later; staff via `/inspect`): +2,500 set XP (greater +10,000), never past Lv 40; used from the set screen with a confirm. A used tome's copy is taken (staff told).
- **Merging**: two different owned sets, both at the max level, tier I-III, not merged before, sharing no bonus family → one set with both sets' 2- and 4-piece bonuses, the look you pick, at **Lv 0** (owner rule), for ◆ 5,000 × (tier A + tier B − 1). One database transaction (unsaved XP written first, both rows locked and re-checked, inputs marked merged and taken off, merge record, crystals with idempotency key `wardrobe_merge:<new entry>`); no unmerge. The inputs' sets can be bought or redeemed again.
- **Warzone** (`warzone.worlds`, default `warzone`): every set counts as 1× whatever its level, only damage reduction (at 50%) and conquest bonuses work, armor points are normalized to diamond-like (`warzone.armor`), no trails. Wearing/merging is refused there (`equip.blocked-worlds`).

Loadouts (W3; defaults, all in `wardrobe.yml → loadout.*`, plan §7, owner L1-L4):
- A preset (per **profile**) holds per armor slot a wardrobe set or "empty" (pieces not in it are taken off and stay in the wardrobe), the pet (hook; "Pets are coming" until pets exist) and per hotbar slot a unique item (custom tool, …); plain items are never saved ("keep"). Save current captures what you wear and the unique items in your hotbar.
- **Slots** (L2): 2 free (`free-slots`), ranks `skyblock.loadout.slots.3`…`.8` (highest counts), plus slots bought with store credits (`loadout_slots_bought`, account-wide, +1 each, at most `bought-max` 3; nothing writes it until the store exists), never more than `max-slots` 8. A preset above your slots (rank lost) is kept but locked.
- **Where** (L4): anywhere except while combat-tagged (`combat-seconds` 10: dealt or took damage from a player or a hostile mob, arrows count), in `blocked-worlds` (warzone), while frozen, during a profile switch or another wardrobe action; **2 s cooldown** (`cooldown-seconds`), shared with wearing/taking off sets. Single wears/take-offs and Wardrobe Chest moves now follow the same combat and freeze rules (`equip.combat-seconds`, LD6).
- **Applying** (L3, dupe-safe, LD4): the player is locked (inventory clicks, drops, pickups, profile switch) and the menu closes; every move is planned first; then **one database transaction** stores the tools leaving the hotbar in the **Wardrobe Chest**, marks the chest tools coming out as being handed out and writes the new worn pieces; only then do the items move in one tick. Swapped-out tools go to the chest (never dropped; a full chest keeps them in the inventory), plain items in a needed slot move to a free slot, vanilla armor under a new piece moves to the inventory. A part that can't happen (tool gone, set gone, no room) is skipped and listed in chat (`partial: true`; `false` = refuse the whole swap). Item ids are kept. A crash or quit at any point is repaired on the next join by the chest recovery (each tool ends in exactly one place).
- Merging two sets re-points presets that wore either set to the merged set (same transaction as the merge).
- Feedback: action bar + chat `Loadout Mining: 4 piece(s), 3 tool(s)`; skipped parts in one line.
- Combat tag for other modules: `core.services().optional(CombatTagService.class)` (`common/combat`, `core.yml → combat.tag-seconds` / `combat.mobs`). Pets: `common/pet/PetHook` (no-op until pets exist).

Staff (no new command, WD25): **Wardrobe** button in `/inspect <player>`: their sets and chest size (`skyblock.wardrobe.staff`, helper+); admins (`skyblock.wardrobe.admin`) give a set, give a Set Token or a Wardrobe Tome (player online), click a set to **set its level** (0, 1, 10, 25, 40, 49, max) or remove it, each with a confirm. Staff test commands (`/wardrobe admin …`) are not built (need owner approval).

For other modules: `core.services().optional(WardrobeService.class)` (`common/wardrobe`): `wornPieces`, `ownedSets`, `setLevel`, `setXp(player, action, amount)` with the action ids `XP_SELL_ITEM`, `XP_SELL_ISLAND_ITEM`, `XP_MINI_BOSS`, `XP_WORLD_BOSS`, `XP_KOTH_TICK`, `XP_KOTH_CAPTURE`, `XP_ENVOY`, `XP_WARZONE_KILL`, `XP_FISH` (or a plain XP activity with raw XP), `levelMultiplier`, `enchantSlots` (E5), `isSetPiece`, `createToken(set, origin, owner, actor)` for crates, `openStaffView`.
