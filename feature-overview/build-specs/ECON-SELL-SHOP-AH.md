### A2. Every block sellable: roots and derived prices
- `sell.yml` gains `roots:` (`ECON-TABLES.md` E, id -> base) and `derive:` (`enabled` true, `factor.<class>` percents, `exclude` list, `overrides.<id>`, `max-depth` 6); `config-version: 2`. Everything already listed keeps its price. The 23 `custom-items.spawner-drops` entries come from `ECON-SPAWNERS.md`.
- New pure `SellDerive` (economy/sell): input `Map<String, Double> priced` (roots + listed, after the multiplier), `List<Recipe>` (`record Recipe(String output, int count, List<List<String>> inputs, RecipeClass cls)`: each input is a list of alternative item keys), factors, exclude set; algorithm: repeat up to `max-depth` rounds: for each recipe whose every input has an alternative with a price, `candidate = factor(cls) * sum(cheapest priced alternative per input) / count`; the output takes `min(existing, candidate)`; stop when nothing changes by more than 1e-9; items in `exclude` or with unpriced inputs stay unsellable; hand prices **above** the derived value are lowered with a console line (that is how loops start); result is an immutable `Map<String, Double>`. `RecipeClass` from the recipe type: crafting shaped/shapeless = `shaping`/`storage`/`decorative`/`dyeing` by the rule table (`ECON-TABLES.md` E; classification by a small pure `RecipeClasses.of(recipe)` table of id patterns: `*_block` with 9 inputs = storage, `*_planks` = shaping, `polished_*`/`*_bricks`/`chiseled_*`/`cut_*`/`smooth_*` = decorative, anything with a dye input = dyeing, smelting/blasting/smoking/campfire = processing, stonecutting = shaping), smithing is skipped.
- Source of recipes: `SellRecipes.fromServer()` reads `Bukkit.recipeIterator()` once on the main thread at enable and reload (about 1,500 recipes, under 50 ms) and converts shaped/shapeless/furnace-like/stonecutting recipes with `RecipeChoice.MaterialChoice`/`ExactChoice` materials only. The derived entries are appended to the catalog (`SellCatalog.withDerived(Map)`, category `blocks`, key = vanilla id, `sellable` true). Tools, armor, weapons, filled containers, enchanted items are never derived (`derive.exclude-types`).
- Offline test data: `modules/economy/src/test/resources/recipes-1.21.5.json`. Produced by the admin command `/eco sell dump-recipes` (writes `plugins/PhoenixSkyblock/recipes-<version>.json`; run once on the test server console by the owner or the developer with permission, then copied into the repo); alternative `./gradlew exportRecipes` only if the build can read the vanilla data without starting a server. **No server is started by the build.**
- No families, no push limit in this release (Principle 0, simpler version of C4 proposal 1 and 3): each item keeps its own 40% to 150% dynamic multiplier. Arbitrage between a block and its parts is bounded by that band, which the shop invariant already assumes; the no-loop proof below holds at every multiplier combination.
- No-loop proof (tests): `NoCraftLoopTest` (for every recipe of the committed export: `price(output) * count <= sum(price(inputs)) * 1.0 + 1e-6` for priced items; property test with random root multipliers 0.4 to 1.5), `DerivedPriceTest` (planks from logs 90%, block from ingots 100%, tag alternatives take the cheapest, unpriced part = unsellable, depth cap, exclude list, hand price above derived is lowered), `RoundingTest` (split sale never pays more than one sale, total under $1 pays 0), `SellKnobTest` (multiplier scales roots, derived and custom items; shop auto price follows), `SellConfigKeysTest` (all new keys exist with defaults).

## 5. Risks and rollback
- **Price level:** `sell.price-multiplier` without `buy.price-multiplier` breaks the x7.5 rule (items hide with "Not for sale right now") and shifts income against fixed sinks (upgrades, Forge). Both knobs 1.0 today; moving them is an owner/C14 decision.
- **Derive engine reads the live recipe registry:** a Paper update can add recipes; `NoCraftLoopTest` on the committed export and the startup self-check (`SellDerive` logs every item whose derived price is above the sum of its parts) catch it; `sell.derive.enabled: false` returns to the listed prices only.
- **`double` base** touches a common record used by the shop tooltips (GUI lane): signature stays source compatible; if the lane changes `SellPrice` first, rebase.
- **Gate fails closed** if the economy module is down: buying pauses (`buy-gate.enabled: false` to open).
- **Bin migration:** rows are drained once at enable; a box that refuses keeps rows and retries each minute; rollback = leave the drain off (`notify`/button gone but rows safe in `ah_collection`).
- **Shop removals** cost builders two clicks; items stay sellable (derived) and counted for island worth.
- **Rollback of data:** all new tables are additive; config version bumps keep owner-edited values.
