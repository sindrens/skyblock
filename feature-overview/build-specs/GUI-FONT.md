# Build spec GUI-FONT: the frame layer (panel, plaque, soft tile, cartoon lettering, logo) as a pack font

Cards: **I7 v4** and **I9 v3** (both Locked 1 Nov 2026), `docs/FORMAT.md` sections 0, 3, 7, G7/G8 (logo surfaces, API only here). Owner answers: `rounds/OWNER_ANSWERS_2026-11-01.md` (V3-Q1 b "full MC Hub look but a little different so we don't steal it", Q2 a, Q3 a, Q4 a, Q5 a, Q9 a, Q18 a, HT-Q1 a). Written 1 Nov 2026 for the `coder` agent. No code in this file. Build order: **GUI-ICONS-FINAL first**, then this spec (branch `q/gui-font`), MENUS-V3 runs in its own lane in parallel.

## 0. Goal and scope
**Goal:** Java players with the pack LOADED see every chest menu as our own panel (one colour, hidden empty slots, a soft tile behind each filled slot, a plaque above the panel with ONE cartoon all-caps noun), plus our logo on the scoreboard title and tab header. Bedrock, no-pack, fail-open, "Plain menus" and kill-switch viewers get the same layout on the plain vanilla chest with the plain title. The art is ours (rounded, ember outline, not MC Hub's), generated by a stdlib Python script; the owner overwrites PNGs by name.

**In scope:** generator, pack assets, font JSON, `common/.../frame` package, `Glyphs.of(viewer)` gate, title builder, `Menu`/`MenuService` hooks, config kill switches, `/pack glyphtest`, "Plain menus" switch, logo helper API, pack module changes, tests, docs.
**Out of scope:** per-menu `title.short` texts for the ~190 menus (framework menus and the menus of MENUS-V3 only; the rest are the rollout list in MENUS-V3 section 9), the HUD lane that calls the logo API, global `generic_54` skin (I7 phase 2e, not built), Bedrock art, icons-before-lines, any font use in lore, chat, scoreboard lines, boss bar, holograms.

## 1. Known unknowns (nothing here was verified on a real 26.3 client; step 1 is the spike) and the safe fallback
| # | Unknown | Gate / tuning | If it fails |
|---|---|---|---|
| U1 | **Draw order:** container title glyphs draw above or below slot items on 26.3 (the GUI renderer was reworked in 1.21.6) | owner screenshots from `/pack glyphtest`: items must be on top of the panel and tiles | **NO-GO: ship nothing visible** (menus stay plain; assets stay in the pack, harmless); no other work is wasted |
| U2 | Title origin x = 8 and baseline = 13 (text y 6 + 7) | exposed vanilla grey at a window edge = offset; change `title_origin_x` / `title_baseline` in `panels.json`, regenerate | tuning loop, no Java change |
| U3 | Bitmap glyph advance = visible width + 1 | `advance_pad` in `panels.json` (default 1); the spike shows a cursor test row | change the number, regenerate |
| U4 | Negative `ascent` accepted (soft tiles use -4 - 18 x row) | spike | `panels.json` `cell_mode: tall`: one tall transparent PNG per row, positive ascent (generator supports both) |
| U5 | Largest glyph 176 x 221 fits the font atlas (all glyphs are at most 256 px) | spike | split the panel into top and bottom glyphs (documented, not built) |
| U6 | Slot hover highlight is hidden under the panel | spike records it | accepted: the tooltip still shows; no fix possible from the server |
| U7 | Plaque clipped at the top at GUI scale 1 to 4 and small windows | spike at 854x480 and 1280x720, scales 1-4 | lower `plaque_extend` |
| U8 | Re-titling an open menu (inventory swap) causes a visible blink or moves the cursor | spike | rate limit (section 6.6) and `title-resend-min-ms`; worst case frame titles are fixed per open and tiles are composed from the filled slots at open |
| U9 | Scoreboard title and tab header logo overflow the row | HUD lane check; ascents `logo/wide` 18 and `logo/small` 8 are in `panels.json` | retune ascent |
| U10 | Geyser really never shows a glyph (it drops `font`) | Bedrock phone each release (decision 78) | `Glyphs` is already empty for Floodgate players, so the worst case is a plain title |
**Safe fallback for everything:** `gui.font.enabled: false` (live, no deploy) or `git revert`. Plain titles and the vanilla chest are always complete (I9 rule 11).

## 2. Facts checked in the code (so the spec uses real names)
- Title path: `MenuService#open` (common/.../menu/MenuService.java ~214-254) builds `menu.title()` first, then `Bukkit.createInventory(menu, rows*9, title)`, `menu.attach(...)`, `menu.build()`, `player.openInventory`. `redrawInPlace` (~264-300) re-builds in the open window and calls `setTitle(view, LEGACY.serialize(title))`.
- **`InventoryView` in Paper 26.3 has only `setTitle(String)`** (checked with `javap` on `paper-api-26.3.build.230-stable`): a legacy string cannot carry `font`. **Frame titles therefore cannot be updated with `setTitle`.** They are updated by swapping the inventory (section 6.6). Adventure 5.2.0 has `Style#font(Key)` and `ShadowColor.none()`.
- `MenuService#onClose` already ignores the close event of an old inventory when `menu.getInventory() != event.getInventory()` ("Same menu instance re-opened"), so a swap is safe.
- Gates today: `PackService#hasPack(Player)` (status `LOADED` only), `Messages#isBedrock(Audience)` (used by `MenuService`), `PackStatusEvent`. `PrivateUse.strip` strips U+E000..U+F8FF from player text and `TypedText` (our whole glyph range is covered).
- `modules/pack`: `PackModule` (`registerCommands`, `PackService`), `PackConfig`, zip task `packZip` builds `resourcepack/pack` into `phoenix-icons.zip`; the SHA-1 is the pack version and `PackUrls.packId("icons")` the stable id. `tools/build_icons.py check` has `SIZE_BUDGET = 150 KB` over the whole tree and only deletes stale files in `assets/phoenix/models/item/icon` and `assets/minecraft/items`, so new font folders are never touched by it.
- Framework message file: `plugin/src/main/resources/messages/menus.yml` (+ tracked copy under `server/`); menus module texts `modules/menus/src/main/resources/messages/navigation.yml`; HUD title is set in `modules/hud/.../Sidebar#title(Component)`.

## 3. Geometry (window-relative pixels; every number comes from `panels.json`/`frame-metrics.json`, never hard-coded in Java)
| Thing | Value |
|---|---|
| Window width | 176; title cursor starts at x = `title_origin_x` (8), glyph top y = `title_baseline` (13) - `ascent` |
| Panel glyph | `p3` 176x167, `p4` 176x185, `p6` 176x221; ascent 13 (top at window top); **every pixel opaque** (the vanilla window is under it, so no rounded corners) |
| Container area | rows x 18 + 17 high, no cells; item (c, r) at (8 + 18c, 18 + 18r) |
| Player half | label strip, then cells at x = 7 + 18c, y = rows x 18 + 30 + 18k (k = 0..2) and the hotbar row at rows x 18 + 88; drawn by the panel art |
| Soft tile `cell` | 18x18 at (7 + 18c, 17 + 18r) = item position - 1; six glyphs `E330..E335`, one per row r with ascent **-4 - 18r** (same PNG file) |
| Plaque | 20 high, widths 80 / 112 / 144 (`s`/`m`/`l`), x = (176 - width) / 2, top at y = -`plaque_extend` (-8); glyph PNG is 21 high (1 transparent row) so ascent = 13 + 8 = 21 is not above its height |
| Lettering | 12 px high cells, top at y = -4 (inside the plaque), ascent 9 + `plaque_extend` = 17; sheet cell 16 x 17 (art in the top 12 rows); text centred in the plaque; inner width 64 / 96 / 128 |
| Logo | one 96x20 PNG; `logo/wide` (scoreboard title) ascent 18 (bottom edge on the title row, overflows upward), `logo/small` (tab header) ascent 8 (spans the line and one blank line below) |
| Space glyphs | `F800..F807` = -1, -2, -4, -8, -16, -32, -64, -128; `F808..F80F` = +1 ... +128 (font `space` provider, no PNG); `Space.move(dx)` writes the binary decomposition (largest first, at most 8 glyphs for |dx| < 256) |
Rule: bitmap `ascent` must not exceed `height`; art that must sit higher than that is padded with transparent rows (the generator computes it).

### 4.1 Commands
| Command | Does |
|---|---|
| `art` | draws every missing sprite as a placeholder in our palette; **never overwrites** an existing PNG (`--only <name>` / `--force-art` redraw, like `build_icons.py`) |
| `pack` | composes the finals from the sprites (or takes `owner-final/<name>.png`), writes both font JSONs and `frame-metrics.json` (advances measured **from the final PNGs**: right-most non-transparent column + `advance_pad`), deletes nothing outside its own folders |
| `sheet` | `frame-sheet.png`: a P6 panel with plaque `UPGRADES`, 12 tiles and the logo at 3x on a game-grey background, and the full letter set |
| `check` | exit 1 when the committed tree differs from what `art` (missing only) + `pack` would write, or a rule fails (4.4) |
| `metrics` | prints the advance table (for the spike log) |
Raise `SIZE_BUDGET` in `tools/build_icons.py` from 150 KB to **250 KB** (the frame layer adds about 20-30 KB; I7 target 200 KB, hard limit 1 MB).
### 4.2 Art rules (placeholders; the owner repaints)
- **Palette:** frame dark ember `#4A1218` outline, brand red `#D1202F` frame, flame gold `#FFC21A` trim, parchment panel `#D9D2C0` with a lighter bevel `#F0E9D6`, cell `#B8B09C` with shadow `#8F8775`, soft tile `#F3EEDF` with edge `#B3AB97`. One colour for every menu (V3-Q9).
- **Panel:** 9-slice of `panel_frame.png` to 176 x H; top band 17 px stays plain parchment (the plaque sits on it, and unmigrated menus show the plain dark-grey title text there: it must stay readable); the "Inventory" label strip stays light; a dark-red divider between the two halves.
- **Plaque:** left cap + n x mid + right cap, ember-red plate, gold trim, rounded corners (transparent corner pixels are fine for the plaque and tile, never for the panel).
- **Lettering (our own style, not MC Hub's):** generated programmatically by `lettering.py` from a stroke table (A-Z, 0-9 and `& ' - ! ? ( ) / . , :`, 48 glyphs; space is a `space` provider of 4 px): each glyph is a short list of polyline strokes on a 10 px tall grid, swept with a 3x3 plus-shaped round brush (rounded ends, no pixel-font corners), 1 px dark-ember outline by 8-neighbour dilation, vertical fill gradient `#FFF3C4` -> `#FFD21A` -> `#F59A00`, a lighter pixel on each round corner, total height 12 px, width 4-8 px (`M`, `W` 9). Colours are baked in, so the text colour is white. `check` asserts: all 48 glyphs non-empty, every pair of glyphs differs in at least 6 pixels, widths 3-9.
- **Logo:** 96x20 max, two lines (`PHOENIX` large in the lettering style, `SKYBLOCK` small) plus a small flame mark, 1 px dark outline, readable on any background; `check` asserts at most 96 x 20.
### 4.3 `frame-metrics.json` (generated; `common/build.gradle.kts` `processResources` copies it to `frame/frame-metrics.json` like `icons/icons.json`)
Fields: `version`, `title_origin_x`, `title_baseline`, `plaque_extend`, `window_width`; `panels.{p3,p4,p6}`: `rows`, `width`, `height`, `advance`, `cp`; `plaques.{s,m,l}`: `width`, `advance`, `inner`, `cp`; `cell`: `size`, `x0`, `y0`, `step`, `advance`, `cp[6]`; `logo.{wide,small}`: `cp`, `advance`, `ascent`, `width`, `height`; `space.neg[8]`, `space.pos[8]`: codepoints with their pixel step; `letters.advance`: char -> advance (visible width + `advance_pad`), `letters.space` 4. Parsed with `YamlConfiguration` (JSON is valid YAML, same trick as `IconCatalog`), no JSON library.
### 4.4 `check` rules (also asserted in Java by `FrameAssetsTest`)
Every provider's PNG exists; `ascent <= height` for every bitmap provider; every glyph PNG at most 256 x 256; panels fully opaque with exactly the section 3 sizes; codepoints unique and inside `E300..E3FF` or `F800..F80F` (never `E000..E1FF`); `chars` unique across both fonts; plaque `height >= ascent`; lettering cell height >= 9 + `plaque_extend`; zip size under budget.

## 5. Font JSON (generated; shape for the coder)
`assets/phoenix/font/frame.json`: one `space` provider with the 16 advances; bitmap providers `{"type":"bitmap","file":"phoenix:font/frame/panel_p6.png","ascent":13,"height":221,"chars":["\uE302"]}`; plaques with `ascent` 21 and `height` 21; six cell providers (same file `phoenix:font/frame/cell.png`, `height` 18, ascents -4, -22, -40, -58, -76, -94, chars `E330..E335`); two logo providers (same file, `height` 20, ascents 18 and 8, chars `E340`, `E341`).
`assets/phoenix/font/title.json`: a `space` provider `{" ": 4}`; bitmap `file phoenix:font/title/letters.png`, `ascent` 17, `height` 17, `chars` = the three rows of the sheet; a second bitmap provider on the **same file** with the lowercase layout (`\u0000` for non-letters) so lowercase text also shows capitals. Only named fonts are used (`phoenix:frame`, `phoenix:title`); `minecraft:default` is never overridden.

### 6.2 Title algorithm (`PanelTitle.build`; c = cursor x, starts at `title_origin_x` = 8)
1. `move(-8)` (c = 0); panel glyph (c += panel.advance); `move(-c)` (c = 0).
2. If `tiles`: for each filled slot of the top inventory in ascending order (slot < rows x 9): `move(7 + 18 x col - c)`, glyph `cell[row]`, c += `cell.advance`.
3. If a plaque fits: `move(plaqueX - c)`, plaque glyph, c += advance; `move(textX - c)`; end the frame run; then a `TITLE` run with the sanitised text (c advances by the letter advances).
4. If there is no plaque text: `move(8 - c)` ends the frame run and the **plain title component is appended** (dark grey text on the panel's top band, at its normal place).
5. A text that is empty, invalid or wider than the large plaque falls back to step 4 (never cut, logged once per menu class).
Golden tests fix the exact strings for P3 empty, P6 with 3 tiles and plaque `SHOP`, P4 with plain title.
### 6.3 `Menu` hooks (`common/.../menu/Menu.java`)
- `public boolean panel()` default `true`: **opt-out for menus whose empty slots are real drop slots** (set `false` in `modules/economy/.../sell/SellMenu`, `modules/progression/.../TaskDeliverMenu`, and any other menu found with `grep -rln "InventoryClickEvent\|InventoryAction" modules` that accepts items: check `modules/enchants`, `modules/tools` forge screens). `TrashMenu` builds its own inventory and is untouched.
- `public final Optional<PanelType> panelType()`: empty when `!panel()` or rows not 3/4/6.
- `public String plaqueKey()` default `null` (message key in `messageModule()`; value is the plaque noun, e.g. `title.short`). Null = panel with the plain title text in its top band (unmigrated menus still get the hidden empty slots and tiles).
- `public boolean frameForced()` default `false` (only `GlyphTestMenu` returns true).
- Package-private: `BitSet filled()` (top inventory slots that hold an item), `void replaceInventory(Inventory)`, `boolean tilesDirty`, `long titleSentAt`, `BitSet shownMask`. `set(...)` marks `tilesDirty` when a slot goes empty <-> filled.

### 6.6 Updating an open frame title (no `setTitle`)
`swapInventory(Player, Menu, Component title)`: `next = Bukkit.createInventory(menu, size, title)`; `next.setContents(old.getContents())`; `menu.replaceInventory(next)`; `player.openInventory(next)`. The client receives one open-screen packet and the contents, replaces the screen without closing it (no cursor reset: the existing in-place design relies on the same client behaviour); the old inventory's close event is ignored by `onClose` (holder inventory mismatch); `MenuOpenedEvent` is NOT fired (it only fires in `open`); no sound. Only called when the filled-slot set or the plaque text changed and the throttle allows it.

### 6.8 Logo helper API (step 4; the HUD lane calls it, this spec does not touch `modules/hud`)
`core.menus().glyphs().forViewer(player).flatMap(FrameGlyphs::logoWide)` for the scoreboard title, `...logoSmall` for the tab header (the caller adds one `\n` blank line under it, section 3 Logo). ## 12. Edge cases and abuse cases
- Players cannot type or rename items into a glyph: `PrivateUse.strip` on chat and `TypedText`; **no player-controlled text is ever put in a title** (plaque text comes only from message files and is `sanitize`d; staff-edited texts that do not fit fall back to the plain title and log once).
- Menus with 1, 2 or 5 rows are never framed; a menu that changes its row count while open already reopens (existing size check).
- A menu whose live refresh flips a tile every tick cannot spam titles: `title-resend-min-ms`.
- Pack becomes LOADED while a menu is open: redraw to framed; pack reload or decline: redraw to plain; Bedrock never.
- Frame titles are not compared with player text anywhere; `Component.equals` is only used to decide whether to swap.
- Performance: a title is built once per open and per tile-set change, cached in a 256-entry LRU, at most about 300 characters; no per-tick work except one boolean per open menu.

## 13. Risks and rollback
| Risk | Mitigation |
|---|---|
| U1 fails on 26.3 | step 1 is a spike; NO-GO ships nothing visible and costs only the committed assets |
| Mojang changes GUI rendering in a game drop | `gui.font.enabled` kill switch; every game drop gets a 15-minute glyph test (I8 checklist ripple GUI-V3-10) |
| Pack download grows | budget 250 KB checked by `build_panels.py check` and `FrameAssetsTest` |
| Panel hides the hover highlight (U6) | accepted and documented |
| Owner art replaces a final with wrong dimensions | `pack` and `check` refuse and name the file |
Rollback: `gui.font.enabled: false` (no deploy) or `git revert` of the step commits; the pack keeps harmless unused fonts until the next build.
